# مرجعُ سلوك ملاحة غوغل — ما هو منشورٌ رسميّاً وما يقابله في رحّال غو

> **طلبُ المالك ٢٠٢٦-١٠-٠٢** (مواصفة الملاحة، الجزء ٠): «اعتبر Google Maps / Navigation SDK
> مرجعاً سلوكيّاً… لا تكتب أيّ خوارزميّةٍ سرّيّةٍ منسوبةٍ إلى Google بلا دليل».
>
> **المصادرُ رسميّةٌ وحدَها**: developers.google.com (Navigation SDK for Android، Roads API،
> Play Services Location) وdeveloper.android.com. **وكلُّ رقمٍ في عمودَي «ما يقابله» و«اختبار
> القبول» اقتراحٌ منّا لا رقمُ غوغل** — إلّا ما نُقل حرفيّاً تحت «المنشور».

**اختصاراتُ المصادر**
- RSLP: `…/navigation/android-sdk/reference/…/RoadSnappedLocationProvider`
- GPSEV: `…/GpsAvailabilityChangeEvent` · NAV: `…/Navigator` · GMAP: `…/GoogleMap`
- FAQ: https://developers.google.com/maps/documentation/navigation/android-sdk/faq
- CAM: https://developers.google.com/maps/documentation/navigation/android-sdk/camera
- EVT: https://developers.google.com/maps/documentation/navigation/android-sdk/events

## ١ · الموقعُ الملتصقُ بالطريق (RoadSnappedLocationProvider)

| | |
|---|---|
| **المنشور** | مزوّدٌ يعطي «مواقعَ ملتصقةً بالطريق» بأسرع ما يمكن (في القيادة خصوصاً)، ومع كلّ موقعٍ علامةُ `IS_ROAD_SNAPPED_KEY` تقول **هل أُلصق فعلاً**. ويُنبَّه أنّ الإلصاقَ قد يخطئ أحياناً. وواجهةُ Roads API (إلصاقُ ١٠٠ نقطةٍ دفعةً) **خدمةٌ خلفيّةٌ مجمّعة** لا لحظيّة. |
| **غيرُ المنشور** | خوارزميّةُ الإلصاق، ونصفُ قطر البحث، ووزنُ الاتّجاه، وهل يفضّل الطريقَ المرسوم. |
| **ما يقابله عندنا** | إلصاقٌ على الجهاز بالطريق المرسوم أوّلاً: الإسقاطُ مقبولٌ إن كانت المسافةُ ≤ max(15م، 1.5×الدقّة) والزاويةُ ≤ 45° ولا رجوعَ للخلف > 20م — **وإلّا يُعرض الخامُّ بعلامة «غير ملتصق»**. |
| **اختبارُ القبول** | إعادةُ رحلةٍ بضجيجٍ جانبيٍّ ±10م: ≥95٪ من المواقع المعروضة على الخطّ، ولا رجوعَ > 20م. ونقطةٌ بعيدةٌ 60م بدقّةٍ جيّدة ⇒ «غير ملتصق» خلال قراءةٍ واحدة. |

## ٢ · الموقعُ الخامُّ وموقعُ الملاحة

| | |
|---|---|
| **المنشور** | الموقعُ الملتصقُ «قد يختلف عن موقع المزوّد المدمج»، و`onRawLocationUpdate` يصل حين لا يتوفّر الملتصق. و`getMyLocation()` مهجورٌ لصالح المزوّدين. |
| **غيرُ المنشور** | تواترُ الخامّ مقابلَ الملتصق، وهل يُستكمَل الملتصقُ بين قراءات الأقمار. |
| **ما يقابله عندنا** | مجريان: **خامٌّ** (للخادم والسجلّ والوصول) و**ملاحيٌّ** (للسهم والكاميرا والتقدّم). **ولا يُرسَل الملاحيُّ للخادم كأنّه مَقيس.** |
| **اختبارُ القبول** | كلُّ إطارٍ للسهم له قراءةٌ خامّةٌ عمرُها ≤ 1.5ث أو حالةُ «جاري البحث عن GPS». والخادمُ لا يتلقّى إلّا الخامَّ بدقّته. |

## ٣ · الحسّاسات

| | |
|---|---|
| **المنشور** | `isGpsValidForNavigation()`: «إشارةُ GPS **أو حسّاساتٌ أخرى** جيّدةٌ بما يكفي». ومثالُ النفق: قد يبقى التوفّرُ صحيحاً إن أبقت الحسّاساتُ الموقعَ موثوقاً. و`Location.getBearing()` «اتّجاهُ حركة الجهاز ولا علاقةَ له باتّجاه الجهاز نفسه». |
| **غيرُ المنشور** | أيُّ الحسّاسات تُدمج، وكيف، وكم يستمرّ التقديرُ قبل إعلان الفقد. |
| **ما يقابله عندنا** | **لا بوصلةَ أثناء القيادة**. اتّجاهُ الأقمار حين تكفي السرعةُ والدقّة. **واختياريّاً لاحقاً**: تقديرٌ قصيرٌ على الطريق بآخر سرعة، حدُّه ~10ث أو 200م ثمّ إعلانُ الفقد. |
| **اختبارُ القبول** | تدويرُ جوالٍ واقفٍ 180° ⇒ لا يتغيّر اتّجاهُ السهم ولا الكاميرا. وفجوةُ نفقٍ 30ث على 50 كم/س ⇒ يتقدّم ≤10ث ثمّ يتوقّف ويظهر «جاري البحث». |

## ٤ · الاتّجاه / الخريطةُ مع اتّجاه السير

| | |
|---|---|
| **المنشور** | `getBearingAccuracyDegrees()` دقّةٌ بالمئين 68، صالحةٌ مع `hasBearingAccuracy()`. وفي وضع المتابعة «تواجه الكاميرا اتّجاهَ السير تلقائيّاً». |
| **غيرُ المنشور** | السرعةُ أو الدقّةُ التي يُجمَّد تحتها الاتّجاه، وثوابتُ التنعيم. |
| **ما يقابله عندنا** | الأولويّة: (١) اتّجاهُ مقطع الطريق الملتصق أثناء الإرشاد، (٢) اتّجاهُ الأقمار إن `hasBearing` والسرعةُ ≥ ~2م/ث والدقّةُ ≤ ~30°، (٣) وإلّا يُثبَّت الأخير. **تنعيمٌ بأقصر زاوية** (359°→0°). |
| **اختبارُ القبول** | واقفٌ بضجيج اتّجاهٍ ±90° ⇒ الكاميرا تتغيّر < 5° في 30ث. ومنعطفٌ 90° على 30 كم/س ⇒ تنتهي الكاميرا من الدوران خلال 2ث بعد التقاطع، **بلا دورانٍ في الجهة الخطأ**. |

## ٥ · كاميرا المتابعة والمنظورات

| | |
|---|---|
| **المنشور** | `followMyLocation(perspective)`: «تتبع الكاميرا موقعَ المستخدم… عادةً عند بدء الإرشاد لدخول منظر القيادة المائل». المنظورات: `TILTED` (مائلٌ باتّجاه المستخدم — «شائعٌ في القيادة»)، `TOP_DOWN_HEADING_UP`، `TOP_DOWN_NORTH_UP`. و`startGuidance()` **لا يحرّك الكاميرا** — على التطبيق أن يستدعي المتابعة. |
| **غيرُ المنشور** | زاويةُ الميل، وموضعُ السهم العموديّ على الشاشة، ومددُ الحركة. |
| **ما يقابله عندنا** | ثلاثةُ أوضاع: مائلٌ مع الاتّجاه (افتراضيّ في الإرشاد)، ومسطّحٌ مع الاتّجاه، ومسطّحٌ للشمال. **وفي المائل يكون السهمُ عند ~70–75٪ من ارتفاع الشاشة** ليُرى الطريقُ أمامه. |
| **اختبارُ القبول** | بدءُ الإرشاد ⇒ متابعةٌ خلال 1ث. وتبديلُ الأوضاع: الشماليُّ يبقى 0°، ووضعا الاتّجاه يُبقيان المقطعَ للأعلى ±10°. |

## ٦ · إعادةُ التوسيط بعد تحريك المستخدم للخريطة

| | |
|---|---|
| **المنشور** | `onCameraStoppedFollowingLocation()`: تخرج الكاميرا من المتابعة «إن حُرّكت بإيماءة المستخدم **أو باستدعاء برمجيّ**». وزرُّ «إعادة التوسيط» يعيد المتابعة. |
| **غيرُ المنشور** | **لا توثيقَ لعودةٍ تلقائيّةٍ بمهلة** — العودةُ المنشورةُ بالزرّ أو باستدعاء التطبيق. |
| **ما يقابله عندنا** | أيُّ إيماءةٍ ⇒ خروجٌ من المتابعة + زرُّ «إعادة التوسيط»؛ والضغطُ ⇒ عودةٌ ناعمة. **والعودةُ التلقائيّةُ بمهلةٍ خيارُ منتَجٍ لنا لا سلوكُ غوغل.** |
| **اختبارُ القبول** | تحريكٌ أثناء الإرشاد ⇒ تنطفئ المتابعةُ في إطارٍ واحد ويظهر الزرّ ولا تتحرّك الكاميرا مع السهم 10ث. والضغطُ ⇒ تعود ويختفي الزرّ. |

## ٧ · التكبير

| | |
|---|---|
| **المنشور** | `setZoomLevel(float)` بين 2 و21. و`showRouteOverview()`: «يعرض الطريقَ المتبقّي حتّى **45 دقيقة** قيادة». |
| **غيرُ المنشور** | التكبيرُ التلقائيّ: هل يتغيّر بالسرعة أو بقرب المنعطف، وبكم. |
| **ما يقابله عندنا** | تكبيرٌ بحسب السرعة مع تقريبٍ عند الاقتراب من منعطف: ~17.5 في المدينة (< 40 كم/س)، ~16 على السريع (> 80)، والتقريبُ إلى ~17.5 خلال 150م من المنعطف. والنظرةُ العامّةُ للطريق المتبقّي بحدّ ~45 دقيقة. |
| **اختبارُ القبول** | سرعةٌ تتصاعد 20→100 كم/س ⇒ تكبيرٌ متدرّجٌ بلا قفزةٍ > 0.5 في الثانية. |

## ٨ · التقدّم: المسافةُ والوقتُ المتبقّيان

| | |
|---|---|
| **المنشور** | `getCurrentTimeAndDistance()` من الموقع الحاليّ للوجهة. ومستمعُ تغيّرهما **بعتبتَي وقتٍ ومسافة** (مثالُ الوثيقة: 60ث أو 100م)، وأسبابُه: الحركة أو المرور أو تغيّرُ الطريق أو الوجهة. |
| **غيرُ المنشور** | طريقةُ حساب الوقت ونموذجُ المرور ومعدّلُ التحديث. |
| **ما يقابله عندنا** | المسافةُ = طولُ الخطّ من الإسقاط إلى الوجهة (**لا خطٌّ مستقيم**). والوقتُ = مجموعُ مدد المقاطع الباقية × عاملُ سرعةٍ ملاحَظٍ محصورٍ 0.7–1.5. وأحداثُ تغيّرٍ بعتبات. |
| **اختبارُ القبول** | طريقٌ 5 كم: المسافةُ تتناقص بلا رجوع (إلّا عند إعادة الحساب) وضمن ±2٪ عند كلّ 500م. |

## ٩ · وقتُ الوصول المتوقّع

| | |
|---|---|
| **المنشور** | الأسبابُ في ٨، ومستمعُ تحديث المرور. |
| **غيرُ المنشور** | تواترُ تحديث المرور وهل يُنعَّم الوقتُ المعروض. |
| **ما يقابله عندنا** | الوصولُ = الآن + الوقتُ المتبقّي، ويُعاد حسابُه مع كلّ تقدّم. **والمعروضُ لا يتغيّر إلّا بدقيقةٍ أو كلَّ 30ث** — ولا يُخفى تغيّرٌ حقيقيٌّ كبير. |
| **اختبارُ القبول** | توقّفٌ 3 دقائق ⇒ يتأخّر الوصولُ ~3 دقائق (±30ث). ولا أكثرَ من تغيّرٍ واحدٍ للنصّ كلَّ 30ث بسرعةٍ ثابتة. |

## ١٠ · إعادةُ الحساب

| | |
|---|---|
| **المنشور** | `onReroutingRequestedByOffRoute()` حين يخرج عن الطريق، و`onRouteChanged()` حين يتغيّر. ويحتفظ الـSDK «ببدائلَ للطريق تحسّباً للخروج عنه». |
| **غيرُ المنشور** | **كيف يُكشف الخروج**: العتباتُ والمدّةُ والتأكيدُ ووزنُ الاتّجاه، وتوقيتُ الطلب. |
| **ما يقابله عندنا** | خروجٌ مؤكَّدٌ فقط إن: البعدُ > max(30م، 2×الدقّة) **و**استمرّ ≥ 3 قراءاتٍ أو 5ث **و**السرعةُ > ~3م/ث. ثمّ طلبُ طريقٍ **من الموقع والاتّجاه الحاليّين**، وطلبٌ واحدٌ معلّق، و≥ 10ث بين الطلبات. وبلا إنترنت يبقى الطريقُ القديم. |
| **اختبارُ القبول** | منعطفٌ فائت ⇒ حدثُ خروجٍ واحدٌ خلال 10ث وطريقٌ جديدٌ خلال 5ث، **ولا إعادةَ حسابٍ من ضجيج 25م على الطريق الصحيح**. وعشرون رحلةً مضطربةً على الطريق ⇒ صفرُ إعادات. |

## ١١ · كشفُ الوصول

| | |
|---|---|
| **المنشور** | `ArrivalListener` لكلّ نقطة، و«خدمةُ الملاحة **لا تتوقّف تلقائيّاً عند الوصول**». ونقطةُ الطريق تقبل: الجانبَ نفسَه من الطريق، والاتّجاهَ المفضَّل، ونقلَها لمكانٍ صالحٍ للتوقّف. والسياجُ الجغرافيُّ ليس من الـSDK — يُبنى في التطبيق من الموقع الملتصق. |
| **غيرُ المنشور** | نصفُ قطر الوصول، وشرطُ السرعة، ومدّةُ البقاء. |
| **ما يقابله عندنا** | الوصولُ = المسافةُ المتبقّيةُ على الطريق ≤ 30م **و**(السرعةُ < 2م/ث أو تجاوزَ نهايةَ الطريق) **و**الدقّةُ ≤ 50م — مرّةً لكلّ نقطة. **وسياجُ العمل (المتجر/الزبون) فحصٌ منفصلٌ لا يُدمج.** |
| **اختبارُ القبول** | اقترابٌ ووقوفٌ ⇒ حدثُ وصولٍ واحدٌ بين 0 و30م قبل النقطة. والمرورُ بجانبها على طريقٍ موازٍ 40م بسرعة 50 ⇒ **لا وصول**. |

## ١٢ · الوجهاتُ المتعدّدة

| | |
|---|---|
| **المنشور** | حتّى 25 نقطة. و`continueToNextDestination()` يزيل الحاليّة ويوجّه للتالية، **والتطبيقُ هو من يقرّر التقدّم** بعد الوصول. |
| **ما يقابله عندنا** | **المتجر ثمّ الزبون رحلةٌ واحدة**: حدثُ وصولٍ لكلّ ساق، وتقدّمٌ صريحٌ (الاستلام)، **بلا إعادة إنشاء الخريطة ولا إيقاف الموقع**. |
| **اختبارُ القبول** | بلا «استلام» يبقى الإرشادُ على ساق المتجر بعد الوصول. وبعد الاستلام ⇒ طريقُ الزبون من الموقع الحاليّ بلا قفزة كاميرا. |

## ١٣ · الإرشادُ الصوتيّ

| | |
|---|---|
| **المنشور** | أوضاع: صامت · اهتزاز · تنبيهاتٌ فقط · تنبيهاتٌ وإرشاد · صوتٌ عبر البلوتوث. والافتراضيّ: الإرشادُ مفعّل. |
| **غيرُ المنشور** | **توقيتُ الجمل** (مسافاتٌ أو أزمنة)، وعددُها لكلّ منعطف، وتأثيرُ السرعة، ومنطقُ الصياغة. |
| **ما يقابله عندنا** | جملٌ **بالزمن لا بالمسافة**: مبكّرة ~30ث (تُترك إن قصر المقطع)، استعداد ~10ث، «الآن» ~3ث أو ≤ 30م. **ولا تُكرَّر جملةٌ لمنعطفٍ واحد.** وجملةٌ بعد إعادة الحساب. وتركيزٌ صوتيٌّ مع خفض الموسيقى. |
| **اختبارُ القبول** | منعطفٌ على 50 كم/س ⇒ الجملُ عند ~417م و~139م و≤ 42م (±20٪) **كلٌّ مرّةً واحدة**. والصامتُ ⇒ صفرُ نطق. |

## ١٤ · ضعفُ الإشارة

| | |
|---|---|
| **المنشور** | `isGpsLost()` بعد ~10ث، للتحذير «جاري البحث عن GPS». و«**لا يخرج الـSDK من الملاحة** بسبب فقد الإشارة». |
| **ما يقابله عندنا** | فقدٌ بعد 10ث بلا قراءةٍ دقّتُها ≤ 50م ⇒ **شريطٌ صامت** «جاري البحث عن GPS» (لا صوت — قرارُ المالك ٢٠٢٦-١٠-٠٢)، وتجميدُ السهم، ولا إنهاءَ للجلسة، والعودةُ بعد قراءتين جيّدتين. |
| **اختبارُ القبول** | قطعُ القراءات 12ث ⇒ الشريطُ عند 10ث (±1) والإرشادُ مستمرّ، ويزول خلال قراءتين بعد العودة. |

## ١٥ · ضعفُ الشبكة

| | |
|---|---|
| **المنشور** | «لا وضعَ بلا اتّصال… لكنّ الـSDK يحفظ مسبقاً معلوماتِ الطريق **لـ15–20 دقيقة** وبدائلَ للخروج عنه». |
| **ما يقابله عندنا** | **نتجاوز غوغل لأنّنا نستضيف أنفسنا**: الطريقُ كاملاً بمنعطفاته في الذاكرة، وقطعُ الخريطة محلّيّةً للمحافظة، وطلبُ إعادة الحساب يُؤجَّل حتّى الاتّصال. |
| **اختبارُ القبول** | وضعُ الطيران 20 دقيقة ⇒ التقدّمُ والوقتُ والصوتُ تعمل، والخريطةُ من القطع المحلّيّة، والخروجُ عن الطريق يُعرض بلا انهيار ويُعاد الحساب خلال 5ث بعد عودة الشبكة. |

## ١٦ · دورةُ حياة الملاحة والخدمة الأماميّة

| | |
|---|---|
| **المنشور** | «يجب استدعاءُ `stopGuidance()` صراحةً». وأندرويد ١٤: **نوعُ الخدمة `location` إلزاميّ**، ولا تُنشأ خدمةُ موقعٍ أماميّةٌ والتطبيقُ في الخلفيّة إلّا بإذن الموقع في الخلفيّة. |
| **ما يقابله عندنا** | خدمةٌ أماميّةٌ واحدةٌ للموقع تبدأ **والتطبيقُ ظاهر**، بإشعارٍ دائمٍ فيه المنعطفُ القادم، وتتوقّف صراحةً عند نهاية الرحلة. |
| **اختبارُ القبول** | أندرويد ١٤: بدءُ الإرشاد يعمل والإشعارُ ظاهر، و10 دقائق والشاشةُ مقفلةٌ بلا فجوةٍ > 5ث. وبعد نهاية الرحلة لا خدمةَ ولا طلبَ موقعٍ باقٍ. |

## ١٧ · السرعة

|---|---|
| **المنشور** | `Location.getSpeed()` «قد تكون أدقَّ من المسافة/الزمن» (قياساتُ دوبلر من الأقمار). وتنبيهاتُ تجاوز الحدّ بنسبٍ مئويّة. |
| **ما يقابله عندنا** | تُعرض سرعةُ الأقمار (`hasSpeed`) مقرّبةً **بأرقامٍ لاتينيّة**، **وصفرٌ ثابتٌ عند الوقوف بهسترة** — لا 1، 0، 2، 0. وحدُّ السرعة من بيانات OSM إن وُجدت وإلّا يُخفى. |
| **اختبارُ القبول** | 60 كم/س ثابتة ⇒ يُعرض 60 ±2. وواقفٌ 3 دقائق ⇒ «0» طوالَها. |

## ١٨ · إعداداتُ مزوّد الموقع للملاحة

| | |
|---|---|
| **المنشور** | `PRIORITY_HIGH_ACCURACY` «أرجحُ أن يستعمل GPS». والفاصلُ **تفضيلٌ لا ضمان**. و`setWaitForAccurateLocation` يؤخّر القراءاتِ الأولى الضعيفة قليلاً. ودقّاتُ الموقع والاتّجاه والسرعة كلُّها بالمئين 68، صالحةٌ مع `hasX()`. **ولا توصيةَ منشورةً بفاصلٍ للإرشاد خطوةً بخطوة** (الخمسُ ثوانٍ لعرض الخرائط لا للملاحة). |
