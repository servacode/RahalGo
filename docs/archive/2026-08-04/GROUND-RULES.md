# القواعد الهندسية الأساسية — ملزمة لكل سطر كود في المشروع

> تُقرأ قبل البدء بأي عمل. أي كود يخالفها يُرفض في المراجعة.

---

## 1. المركزية المطلقة (Single Source of Truth)

### 1.1 النصوص واللغة (i18n مركزي)
- **ممنوع منعاً باتاً** كتابة أي نص ظاهر للمستخدم داخل الكود مباشرة (Hardcoded strings).
- كل النصوص في ملفات ترجمة مركزية: `ar` هي اللغة الأساسية والافتراضية، والبنية جاهزة لإضافة أي لغة لاحقاً (en، ku...) بملف واحد دون تعديل أي شاشة.
  - الويب: نظام i18n موحد لكل تطبيقات Next.js (حزمة مشتركة `web/packages/i18n`).
  - الأندرويد: `strings.xml` حصراً.
  - الخادم: رسائل الأخطاء والإشعارات بمفاتيح ترجمة، لا نصوص مباشرة.
- كل نص جديد يُضاف بمفتاح واضح التسمية: `orders.status.preparing` لا `text1`.

### 1.2 التصميم (Design Tokens مركزية)
- **ممنوع** استخدام لون أو خط أو قياس مباشر في أي مكوّن (`#0E7490` داخل شاشة = مخالفة).
- كل القيم من مصدر واحد:
  - الويب: حزمة مشتركة `web/packages/ui` (ألوان، خطوط، مسافات، ظلال، مكونات أساسية Button/Input/Card...) تستهلكها كل التطبيقات عبر Tailwind CSS Variables.
  - الأندرويد: `Theme` مركزي واحد (Compose Theme) لكل من تطبيقي الزبون والسائق.
- تغيير لون العلامة = تعديل سطر واحد ينعكس على كل المنظومة.

### 1.3 إعدادات العمل الديناميكية (Config-Driven)
كل ما يلي **يُخزَّن في قاعدة البيانات ويُدار من لوحة الأدمن** — تغييره لا يتطلب أي نشر جديد:
- رسوم التوصيل لكل منطقة، الحد الأدنى للطلب، مهل القبول والتصعيد.
- نسب العمولات (متاجر، سائقون، مندوبون)، السقف النقدي.
- الفئات (مطاعم/بقالة/صيدلية...) وترتيبها وأيقوناتها — إضافة فئة جديدة من اللوحة.
- البانرات، النصوص الترويجية، أوقات الدوام، رسائل الواتساب القالبية.
- مفاتيح التشغيل (Feature Flags): تفعيل/تعطيل أي ميزة من اللوحة.

## 2. التصميم المتجاوب وRTL أولاً
- **RTL-First**: الواجهة تُصمَّم عربية من اليمين لليسار أولاً، وتنقلب تلقائياً عند إضافة لغة LTR (استخدام الخصائص المنطقية حصراً: `margin-inline-start` لا `margin-left`).
- **Mobile-First**: كل صفحة ويب تُبنى للجوال أولاً ثم تتوسع (أغلب زبائن الرقة على هواتف) — نقاط القياس الموحدة: `sm 640 / md 768 / lg 1024 / xl 1280`.
- لوحات الإدارة تعمل كاملةً على الجوال أيضاً (موظف العمليات قد يعمل من هاتفه).
- **نظام العرض المزدوج إلزامي لكل شاشات القوائم**: كل قائمة تُعرض جدولاً وبطاقات
  عبر `DataView` المركزي من `@rahalgo/ui` (تعريف أعمدة واحد يغذي الوضعين)،
  مع `ViewToggle` وتفضيل محفوظ لكل مستخدم لكل شاشة — ممنوع بناء جدول يدوي.
- الخط العربي المعتمد: **IBM Plex Sans Arabic** (مجاني، احترافي، ممتاز للأرقام والجداول) — من الحزمة المشتركة حصراً.

## 3. معايير الكود

### الخادم (Go)
- بنية طبقية واضحة: `handlers → services → repositories` — منطق العمل في الخدمات حصراً، لا SQL في المعالجات.
- `gofmt` + `golangci-lint` إلزاميان (يفشل الـCI بدونهما).
- الهجرات (Migrations) مرقمة ومُراجعة — **ممنوع** تعديل هجرة سابقة بعد دمجها.
- كل خطأ يُعاد بصيغة موحدة: `{code, message_key, details}`.
- اختبارات وحدة لكل خدمة حرجة (الطلبات، المالية، الإسناد).

### الويب (Next.js + TypeScript)
- `strict: true` في TypeScript — **ممنوع** `any` إلا بتبرير موثق.
- ESLint + Prettier إلزاميان، مكونات الواجهة من `packages/ui` حصراً.
- Monorepo بـ**pnpm workspaces + Turborepo**: `apps/` (customer, admin, merchant, sales) و`packages/` (ui, i18n, api-client, config).
- عميل API واحد مولَّد من توثيق OpenAPI — **ممنوع** كتابة `fetch` يدوي مبعثر.

### الأندرويد (Kotlin + Compose)
- معمارية MVVM + طبقة بيانات موحدة، حقن تبعيات بـHilt.
- وحدة مشتركة `core` (الشبكة، الثيم، النماذج) بين تطبيقي الزبون والسائق.

## 4. قواعد Git والعمل
- الفرع الرئيسي `main` محمي — العمل بفروع ميزات + Pull Request + مراجعة.
- رسائل الالتزام بصيغة Conventional Commits: `feat:` `fix:` `docs:` `refactor:`...
- كل ميزة تكتمل = تحديث `docs/PROGRESS.md` في نفس الـPR.
- CI إلزامي: بناء + فحص + اختبارات على كل PR.

## 5. الأمان (غير قابل للتفاوض)
- الأسرار في متغيرات بيئة حصراً — **ممنوع** أي سر في الكود أو Git.
- كلمات المرور: Argon2id. الجلسات: JWT قصير العمر + Refresh Token قابل للإبطال.
- كل نقطة API محمية بصلاحيات RBAC صريحة + Rate Limiting.
- سجل تدقيق لكل عملية حساسة (مالية، تعديل صلاحيات، إلغاء طلبات).

## 6. الأداء والصمود
- كل قائمة مرقّمة الصفحات (Pagination) — لا استعلامات مفتوحة.
- فهارس قاعدة البيانات تُراجع مع كل هجرة.
- التطبيقات تتحمل انقطاع الشبكة: تخزين محلي + إعادة محاولة + مزامنة.
- زمن استجابة API المستهدف: أقل من 200ms للعمليات الاعتيادية.
