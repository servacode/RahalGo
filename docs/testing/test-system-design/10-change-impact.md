# محرّكُ أثر التغيير

> §٤٣ · §٤٤ · §٥١ · §٥٢ من طلب المالك.
> **وهذا قلبُ المنظومة** — **وهو ما يجيب سؤالك الأصليّ.**

---

# السؤال

> **إذا عُدّل شيءٌ لاحقاً، كيف يعرف النظامُ بنفسه ما الذي يجب اختبارُه؟**

**والجوابُ رسمٌ بيانيٌّ مولَّدٌ يربط الملفَّ بالاختبار عبر حقيقة المنتج.**

---

# الرسمُ البيانيّ

```
ملفٌّ تغيّر
   │
   ├─ Go     → الحزمة → الدوالُّ المُصدَّرة → المعالجاتُ التي تناديها
   │                                        → الأبوابُ في الموجّه
   ├─ SQL    → الجداول → كلُّ معالجٍ يمسّها
   ├─ Kotlin → الوحدة → التطبيقاتُ التابعة → شاشاتُها
   ├─ TSX    → الصفحة → أبوابُها
   └─ إعداد  → قرّاؤه → التدفّقاتُ المتأثّرة
                 │
                 ▼
            TEST_TRUTH
                 │
                 ▼
    التدفّقاتُ المتأثّرة → الاختباراتُ المطلوبة → الوضع
```

## كيف تُبنى كلُّ حافّة — **بلا يدٍ بشريّة**

| الحافّة | الأداة | القائمُ اليوم |
|---|---|---|
| **ملفُّ Go ← حزمة** | `go list -deps` | ✅ **معياريّ** |
| **حزمة ← معالج** | **`go/ast`** | ✅ **استُعمل في هذا المشروع فعلاً** |
| **معالج ← باب** | **تحليلُ `server.go`** | ✅ **استُعمل — ٢٩١ باباً** |
| **معالج ← جدول** | **استخراجُ SQL من الجسم** | ⚠️ **تقريبيٌّ ويُراجَع** |
| **جدول ← هجرة** | **مسحُ `migrations/`** | ✅ |
| **باب ← تدفّق** | **`TEST_TRUTH`** | **يُبنى** |
| **تدفّق ← اختبار** | **`TEST_TRUTH`** | **يُبنى** |
| **إعداد ← قارئ** | **`grep` على مفتاحه** | ✅ **بسيطٌ وموثوق** |
| **وحدةُ كوتلن ← تطبيق** | **`settings.gradle` + الاعتماديّات** | ✅ |

**وسبعٌ من تسعٍ قابلةٌ للبناء بأدواتٍ قائمةٍ في المشروع أو معياريّة** —
**والثامنةُ (المعالج ← الجدول) تقريبيّةٌ ويُصحَّحها إنسانٌ في `TEST_TRUTH`.**
