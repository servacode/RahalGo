## ⚠️ `OBS-A1` — **الإعداداتُ مفتوحةٌ لـ`ops` و`finance`**

**فموظّفُ عمليّاتٍ يبدّل `sales.commission_percent` و`merchants.commission_percent`
و`pricing.margin_fixed`** — **وهي مفاتيحُ ربح المنصّة كلِّها.**

(`server.go:944`)، **وتبديلُ نسبة العمولة مفتوحٌ للثلاثة.**

**ولا أعدّه عيباً**: **قد يكون قرارَ تفويضٍ مقصوداً.** **وهو `AQ-1` في §٢٥.**

## ⚠️ الرصيدُ المحجوز — **غيرُ موجودٍ إطلاقاً**

```sql
-- 0010_wallets.sql:6
balance bigint NOT NULL DEFAULT 0 CHECK (balance >= 0)
```

**رقمٌ واحدٌ لا طبقات.** **ولا `available` ولا `reserved` ولا `pending`.**

**والأثرُ اليومَ محتمَل**: **طلبُ السحب لا يحجز** — **فالمندوبُ يطلب سحبَ
كلِّ رصيده، ثمّ تُقيَّد له عمولةٌ، ثمّ يُصرَف الطلبُ القديمُ بمبلغه القديم.**
**ولا خطأَ يقع — لكنّ الأرقامَ لا تعني ما يظنّه من يقرؤها.**

```
FINANCIAL CONTROL GAPS = 4
    FC-1  لا مفهومَ رصيدٍ محجوز — والسحبُ لا يحجز
    FC-2  لا حالَ PROCESSING ولا REVERSED في السحب
    FC-3  CHECK (balance >= 0) يمنع الالتزامَ السالب — RQ-5 · PG-6
    FC-4  لا سطحَ يُظهر عمليّةً ماليّةً وقعت نصفَها — §٢٠
```

## و`FC-3` أثقلُها — **وهو ما يجعل `RQ-5` غيرَ قابلٍ للتنفيذ كما هو**

**عقدُك يقول**: **الاستردادُ يعكس عمولةَ المندوب** · **وإن كانت قد سُحبت،
تُعالَج التزاماً سالباً ولا يُمحى التاريخ.**

**والقيدُ `CHECK (balance >= 0 OR is_treasury)` يرفض القيدَ المقابل** —
**فتسقط المعاملةُ كلُّها، ولا يقع الاستردادُ أصلاً.**
**فيُحرَم الزبونُ مالَه بسبب رصيدِ طرفٍ ثالث.**

**ولا يُمسّ الدفترُ إلّا بقرارٍ صريح** — **وهذا قرارٌ في بنية الدفتر لا سطرٌ
في دالّة.** **وهو `AQ-3`.**
