# ٠ · الحالُ اليومَ — **مُقاسٌ لا مفترَض**

**يُكتب أوّلاً حتّى يُعرف ما يُبنى وما هو قائم.**

| البند | الحقيقةُ المقيسة |
|---|---|
| **طرقُ الدفع** | **اثنتان لا ثالثةَ لهما**: `cash` · `wallet` — `orders/service.go:458` |
| **ولا دفعَ إلكترونيٌّ إطلاقاً** | قِيس: لا مزوّدَ ولا بوّابةَ ولا خُطّاف |
| **شحنُ المحفظة** | **يدويٌّ من الإدارة وحدَها** — `admin_wallet_handlers.go:45`: `topup · compensation · adjustment · payout` |
| **ومصدرُ رصيد الزبون اليوم** | **«شحنٌ سلّمه نقداً أو استرجاعُ طلب»** — نصُّ `payout_handlers.go:85` |
| **السحب** | `POST /me/payouts` → **الإدارةُ تقرّر** (`/admin/payouts/{id}/decide`) |
| **من يطلبه** | **`sales` · `driver` · `merchant`** — `payoutRoles` ✅ **والثلاثةُ الذين طلبتَهم قائمون** |
| **حدُّه** | `payouts.min_amount` |
| **والدفعُ الفعليّ** | **خارجَ المنصّة** — قرارُ الإدارة يُقيَّد في الدفتر، **والتسليمُ نقداً** |
| **الدفتر** | `wallet_transactions` + `wallets.balance` بقيد `>= 0` (والخزينةُ مستثناة) |
| **منعُ التكرار** | **بنيةٌ قائمةٌ وتعمل** — `idempotency.go` · **و`/payouts/{id}/decide` ملفوفةٌ بها** ✅ |
| **التدقيق** | `finance.*` — **١٤ فعلاً ماليّاً كلُّها مدقَّقة** ✅ |

> **فالبنيةُ الماليّةُ قائمةٌ وناضجة** — **والناقصُ مزوّدٌ خارجيٌّ وحدَه**،
> **وحالاتُ دفعٍ مستقلّةٌ عن حال الطلب.**

# ١ · `XPRQ-PAY-01` — دفعُ الطلب بشام كاش

```
ORDER → SHAM CASH PAYMENT ATTEMPT → PROVIDER VERIFICATION → PAYMENT CONFIRMED
```

## ما لا يُعدّ دفعاً — **أربعةٌ نصّاً**
**ضغطُ الزبون «دفعتُ»** · **إرسالُ صورة** · **فتحُ رابط الدفع** ·
**ورجوعُ التطبيق من شام كاش.**
**والدفعُ لا يثبت إلّا بتأكيدٍ من المصدر الموثوق الذي يوفّره المزوّد.**

## ما يجب أن يُتحقَّق منه — ستّة
```
provider transaction / reference
order / payment attempt
amount
currency
status
لم تُستعمل هذه العمليّةُ من قبل        ← منعُ إعادة الاستعمال
```

## الذرّيّة
**`PAYMENT MUST BE IDEMPOTENT`** — **وتأكيدٌ يصل مرّتين**:
```
لا دفعٌ يتكرّر · ولا قيدٌ في الدفتر يتكرّر · ولا أثرٌ ماليٌّ للطلب يتكرّر
```

## حالاتُ الدفع — **منفصلةٌ عن حال الطلب**
```
PENDING · VERIFYING · PAID · FAILED · CANCELLED · REFUNDED
```

**⚠️ وهذا ينشئ آلةَ حالاتٍ ثانيةً في المنصّة** — **وأربعَ عشرةَ حالةَ طلبٍ
قائمةً لا تُخلط بها.** **والعلاقةُ بينهما تُصمَّم صراحةً.**

---

# ٢ · `XPRQ-PAY-02` — شحنُ المحفظة بشام كاش

```
WALLET TOPUP ATTEMPT → SHAM CASH PAYMENT → SERVER VERIFICATION
→ WALLET CREDIT → LEDGER ENTRY → CUSTOMER NOTIFICATION
```

**ولا يُضاف مبلغٌ قبل تحقّقٍ ناجح.**
**و١٠٠٬٠٠٠ ل.س مدفوعةٌ ومُتحقَّقٌ منها ⇒ تُضاف مرّةً واحدةً لا غير.**

## ما يجب أن تملكه الإدارةُ لاحقاً — ثمانية
```
تشغيلُ الشحن وإطفاؤه · أدنى مبلغ · أقصى مبلغ · حالُ العمليّة
مرجعُ المزوّد · المرجعُ الداخليّ · سببُ الفشل
أوقاتُ الإنشاء والتحقّق والاكتمال
```

**⚠️ والأربعةُ الأولى مفاتيحُ إعداداتٍ جديدة** — **ولا وجودَ لها في المعجم**
(١١٨ مفتاحاً، ولا واحدَ للدفع). **والباقيةُ حقولُ جدولٍ جديد.**

# ٣ · `XPRQ-PAY-03` — السحبُ الآليُّ إلى شام كاش

```
AVAILABLE BALANCE → WITHDRAWAL REQUEST → OWNERSHIP / ELIGIBILITY VERIFICATION
→ SHAM CASH PAYOUT → PROVIDER CONFIRMATION → LEDGER SETTLEMENT
```

| الدور | ما يسحبه | أقائمٌ اليوم؟ |
|---|---|---|
| **المتجر** | مستحقّاتُ المبيعات والتسويات | **الطلبُ قائمٌ والدفعُ يدويّ** |
| **السائق** | أرباحُه ومستحقّاتُه | **كذلك** |
| **المندوب** | عمولاتُه | **كذلك** |

**والهدفُ التشغيليُّ المعلَن**: **تقليلُ الدفع النقديّ اليدويّ إلى أدناه** —
**والنقدُ استثناءٌ عند الضرورة.**

## حالاتُ السحب
```
PENDING · PROCESSING · COMPLETED · FAILED · REVERSED
```

## القاعدةُ المالية — **صريحةٌ ومُلزِمة**
> **إن فشل السحبُ لا يجوز أن يخسر المستخدمُ رصيدَه.**
> **ولا يقع الخصمُ النهائيُّ إلّا وفق الحقيقة الماليّة الموثوقة.**

**⚠️ وهذا يمسّ ثابتاً قائماً**: `wallets.balance CHECK (balance >= 0)` —
**والخصمُ قبل تأكيد المزوّد يخالف القاعدةَ أعلاه، والخصمُ بعده يفتح نافذةَ
سحبٍ مزدوج.** **فالتصميمُ يحتاج حجزاً (`hold`) لا خصماً** — **ولا وجودَ
لمفهوم الحجز في الدفتر اليوم.**

# ٤ · `XPRQ-PAY-04` — ملكيّةُ حساب شام كاش

**الحسابُ المرتبطُ بالسحب لصاحب حساب رحّال غو نفسِه، أو لمن فُوِّض قانونيّاً.**

| الدور | الشرط |
|---|---|
| **السائق** | **حسابُه هو** |
| **المندوب** | **حسابُه هو** |
| **المتجر** | **باسم صاحبه** · **أو باسم مخوَّلٍ رسميّاً** حسب نموذج الحساب التجاريّ لاحقاً |

**ولا يُسحب مالٌ إلى حساب طرفٍ ثالثٍ عشوائيّ.**

## ⚠️ والاسمُ وحدَه ليس دليلَ ملكيّة — **نصُّ العقد**
**لأنّه يختلف كتابةً وترتيباً وإملاءً وعربيّةً وإنكليزيّة.**

**والدليلُ من وسيلة المزوّد الرسميّة**:
```
Account ID · Wallet ID · Verified Phone · Provider identity fields
أو أيُّ تحقّقِ ملكيّةٍ رسميٍّ متاح
```
**والاسمُ عاملُ تحقّقٍ إضافيٌّ لا غير.**

---

# ٥ · قاعدةُ الأمن — **تبديلُ حساب السحب**

**عمليّةٌ ماليّةٌ حسّاسة**، ويخضع لاحقاً لـ:
```
strong re-authentication · ownership verification · audit log
notification to account owner · وربّما security hold قبل أوّل سحبٍ للحساب الجديد
```

**⚠️ وثلاثةٌ منها تصطدم بمخاطرَ مسجَّلة**:
**`R16`** إبطالُ الجلسات يفشل مفتوحاً · **`R12`** ثلاثُ طبقاتِ تدقيقٍ تموت
بسياق الطلب · **`D14`** موقوفٌ يفتح قناةَ بثّ. **فالمصادقةُ القويّةُ تُبنى
على أساسٍ فيه هذه الثلاثة.**

# ٦ · بنيةُ المزوّد — **لا ربطَ صلبٌ بشام كاش**

```
Payment Provider  /  Payout Provider      ← تجريدٌ أوّلاً
أوّلُ مزوّد: SHAM_CASH
```

**حتّى يُضاف مزوّدٌ ثانٍ بلا إعادةِ بناءٍ لـ**: دفعِ الطلب · شحنِ المحفظة ·
السحب.

**والسابقةُ قائمةٌ في المشروع**: **`OTP_PROVIDER`** (`dev` · `whatsapp`)
و**`auth.otp_channel`** — **فالنمطُ معروفٌ ومطبَّقٌ مرّةً.**

# ٧ · CROSS-SYSTEM IMPACT MAP

| النظام | ما يمسّه |
|---|---|
| **تطبيقُ الزبون** | **طريقةُ دفعٍ ثالثة** · **شاشةُ شحنِ محفظة** · **حالاتُ دفعٍ يراها** · **ونصوصُها بعقد `PC-3`**: «كلُّ حالٍ تُفسّر ما وقع» |
| **تطبيقُ المتجر** | **سحبٌ إلى شام كاش** · **وربطُ حسابٍ بتحقّقِ ملكيّة** |
| **تطبيقُ السائق** | **كذلك** · **وأثرٌ على `D7`**: **سحبٌ آليٌّ يخفض `held` فيفتح سقفَ النقد** |
| **تطبيقُ المندوب** | **كذلك — عمولاتُه** |
| **لوحةُ الإدارة** | **ثمانيةُ حقولٍ للعمليّات** · **ومفاتيحُ تشغيلٍ وحدودٍ جديدة** · **وشاشةُ مطابقةٍ (reconciliation)** |
| **دورةُ الطلب** | **آلةُ حالاتٍ ثانيةٌ منفصلة** — ولا تُخلط بالأربعَ عشرةَ |
| **المحافظُ والدفتر** | **قيدٌ لكلّ تحقّقٍ ناجح** · **ومفهومُ حجزٍ لا وجودَ له اليوم** |
| **الخزينة** | **مالٌ يدخل ويخرج من قناةٍ جديدة** — **والفحوصُ الثلاثةَ عشرَ لا تعرفها** |
| **التسويات** | **تسويةُ السائق والمتجر تصير آليّةً** |
| **الإشعارات** | **تأكيدُ شحنٍ وتأكيدُ سحبٍ وفشلُهما** |
| **سجلُّ التدقيق** | **أفعالٌ ماليّةٌ جديدةٌ كلُّها تُدقَّق** — و`AUDIT_MAP` يزيد |
| **منعُ التكرار** | **البنيةُ قائمة** ✅ — **وتُستعمل لتأكيد المزوّد** ⚠️ **و`R8` يمسّها** |
| **الاسترداد** | **`REFUNDED` تصير حالَ دفعٍ لا حالَ طلبٍ فقط** |
| **التعافي من الفشل** | **`FAILED` و`REVERSED` بلا خسارةِ رصيد** |
| **الأمنُ والإساءة** | **`R9` لا حدَّ معدّلٍ عامّ** — **ونقطةُ دفعٍ بلا حدٍّ بابُ إساءة** |

# ٨ · ما يصطدم بما هو قائم — **سبعةٌ تُسجَّل**

| # | الاصطدام | الأثر |
|---|---|---|
| ١ | **لا مفهومَ «حجز» في الدفتر** | **`XPRQ-PAY-03` يحتاجه ليمنع خسارةَ الرصيد ويمنع السحبَ المزدوج** |
| ٢ | **`CHECK (balance >= 0)`** | **الخصمُ المبكّرُ يخالف العقد، والمتأخّرُ يفتح نافذة** |
| ٣ | **`moneycheck` ١٣ فحصاً ولا واحدَ للدفع** | **`TIG-3` يتّسع** — **قناةٌ ماليّةٌ بلا حارسٍ في الدفتر** |
| ٤ | **`R8` مفتاحُ التكرار يعلق `in_progress` يوماً** | **وتأكيدُ الدفع يعتمده** |
| ٥ | **`R9` لا حدَّ معدّلٍ عامّ** | **نقطةُ تأكيدِ دفعٍ مكشوفة** |
| ٦ | **`D5` المصروفُ والخزينةُ بلا ذرّيّة** | **النمطُ نفسُه سيتكرّر في الدفع إن لم يُعالَج** |
| ٧ | **`R16` الإبطالُ يفشل مفتوحاً** | **والمصادقةُ القويّةُ لتبديل الحساب تُبنى عليه** |

**ولا يُصلَح شيءٌ منها الآن** — **تُسجَّل ليُبنى عليها.**
