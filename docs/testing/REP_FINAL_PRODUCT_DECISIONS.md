# `RQ-3` — **مندوبان يسجّلان المتجرَ نفسَه** · **APPROVED**

## العقد

**الأوّلُ تسجيلاً صحيحاً ومثبتاً زمنيّاً هو صاحبُ العلاقة.**
**ولا يُنشأ المتجرُ مرّتين بهويّة/رقمٍ واحد.**

**وإن حاول الثاني**: **لا مرشَّحَ مكرَّر** · **ولا عمولةَ ولا ملكيّة** ·
**ورسالةٌ واضحةٌ أنّ المتجرَ مسجَّلٌ مسبقاً.**
**وإن نفذ تكرارٌ رغم الحارس، تبقى النتيجةُ حتميّةً ولا تُنتج عمولتين.**

## المقابلةُ بالكود — **وهذه أضعفُ نقطةٍ قِيست**

| الطبقة | أفيها حارس؟ |
|---|---|
| **`POST /rep/leads`** | ❌ **لا فحصَ هاتفٍ ولا اسمٍ ولا نقطة** — `leads_handlers.go:495` |
| **جدولُ `merchant_leads`** | ❌ **لا قيدَ فريدٍ إطلاقاً** — `0021_merchant_leads.sql` |
| **`CreateMerchant`** | ❌ **لا فحصَ متجرٍ قائمٍ بالهاتف نفسِه** |
| **جدولُ `merchants`** | ❌ **`phone` بلا `UNIQUE` · و`owner_user_id` فهرسٌ لا قيد** — `0004_catalog.sql:26,37` |
| **`convertLead`** | ✅ **`merchant_id != nil` يمنع تحويلَ المرشَّح **نفسِه** مرّتين** — **ولا يرى مرشَّحاً ثانياً لمتجرٍ ثانٍ** |

**فأربعُ طبقاتٍ بلا حارسٍ واحد**، **والخامسةُ تحرس شيئاً آخر.**

## والأثرُ الفعليّ

**مندوبان يسجّلان «مطعم النور» بالرقم نفسِه ⇒ مرشَّحان مستقلّان.**
**والأدمنُ يحوّلهما فيُنشأ متجران**، **و`resolveOwner` يربط الاثنين بحساب
صاحبِ الرقم نفسِه** (`EnsureUserWithRole` تُرجع المستخدمَ القائم).

**فيصير**: **متجران في السوق · صاحبٌ واحد · ومندوبان يقبضان كلٌّ عن متجره.**
**وهو بعينه ما يمنعه العقد.**

**والحتميّةُ التي طلبتَها غيرُ موجودة**: **لا ترتيبَ ولا فوزَ للأوّل** —
**من يحوّله الأدمنُ أوّلاً يفوز.**

```
RQ-3 = CLOSED
RQ-3 CONTRACT GAPS = 3
    PG-2  لا فحصَ ازدواجٍ عند إنشاء المرشَّح — ولا رسالةَ «مسجَّلٌ مسبقاً»
    PG-3  لا قيدَ فريدٍ في القاعدة يمنع التكرار عند السباق
    PG-4  لا قاعدةَ أسبقيّةٍ حتميّة — الفوزُ لمن يُحوَّل أوّلاً لا لمن سجّل أوّلاً
```

**و`PG-3` هي الطبقةُ التي طلبتَها نصّاً**: «**إذا وُجد سباقٌ أو مسارٌ يسمح
بالتكرار رغم الحارس، تبقى النتيجةُ حتميّةً ولا تُنتج عمولتين**» —
**وحارسُ التطبيق وحدَه لا يفي بها، والقيدُ في القاعدة يفي.**

# `RQ-4` — **منطقةُ عمل المندوب** · **APPROVED**

## العقد

```
REP TERRITORY = NOT A HARD OPERATIONAL RESTRICTION
```

**مندوبُ الرقّة يسجّل متجراً في دمشق.** **ولا يُنشأ قيدٌ جغرافيٌّ عليه.**

**والمطلوبُ للمراقبة والتخطيط لا للمنع**: **أين سجّل متاجرَه · وأين نشط
ميدانيّاً إن اعتُمد ذلك · وآخرُ مناطق نشاطه · وأين لا مندوبَ نشطاً.**

## المقابلةُ بالكود

| ما يوجبه العقد | الحال | الحكم |
|---|---|---|
| **لا قيدَ جغرافيّ** | ✅ **لا وجودَ لأيّ قيدٍ إطلاقاً** — **لا عمودَ ولا فحصَ ولا شرط** | ✅ **مُستوفىً بالكامل** |
| **أين سجّل متاجرَه** | ✅ **`merchants.district_id` و`location`** — **قابلٌ للاستخراج اليومَ** | ✅ **قائم** |
| **أين نشط ميدانيّاً** | ❌ **لا تتبّعَ زيارات** | ❌ `G-3` |
| **آخرُ مناطق نشاطه** | ❌ **لا موقعَ للمندوب حيّاً ولا آخِراً** | ❌ `G-1` |
| **أين لا مندوبَ نشطاً** | ❌ **لا تغطيةَ تُطرح منها** | ❌ `G-2` |
| **أيُّ فرعٍ يتبعه** | ❌ **لا مفهومَ فرعٍ في المخطّط** | ❌ `G-4` |

**وهذا القرارُ يقلب معنى الفجوات الأربع**: **كانت تُقرأ نقصَ بنيةِ منعٍ** —
**وصارت تُقرأ نقصَ بنيةِ رصد.** **والأخفُّ حكماً والأدقُّ وصفاً.**

**والبندُ الوحيدُ المستوفى بالكامل هو الأهمّ**: **لا قيدَ يمنع مندوباً من
العمل — ولا سطرَ يحتاج حذفاً.**

```
RQ-4 = CLOSED
REP GEO RESTRICTION = NONE — ولا يُنشأ
REP OPERATIONS MAP / TERRITORY GAPS = 4   (G-1 · G-2 · G-3 · G-4 — رصدٌ لا منع)
```

# `RQ-5` — **الاستردادُ يعكس عمولةَ المندوب** · **APPROVED**

## العقد

```
ORDER REVENUE REVERSED → RELATED REP COMMISSION REVERSED
```

**ولا يجوز**: **يسترد الزبونُ مالَه · وتنعكس مستحقّاتُ المتجر والمنصّة ·
وتبقى عمولةُ المندوب قابلةً للسحب.**

**والعمليّةُ دفتريّةٌ قابلةٌ للتدقيق.** **وإن كانت العمولةُ قد سُحبت فعلاً،
تُعالَج التزاماً أو رصيداً سالباً وفق النظام المالي — ولا يُمحى التاريخ.**

## المقابلةُ بالكود

**`reverseCommissions` تعكس اثنين من ثلاثة** (`transitions.go:1010-1098`):

| الطرف | الحال |
|---|---|
| **مستحقُّ المتجر** | ✅ **`ApplyTx(-amount, "merchant_earning")`** لكلّ مطبخٍ قبض |
| **لقطةُ عمولة المنصّة** | ✅ **`UPDATE orders SET platform_commission = 0`** |
| **عمولةُ المندوب** | ❌ **لا قيدَ عكسٍ إطلاقاً** |

**والدالّةُ تنتهي بثلاثة حرّاسٍ يحرسون فعلاً غيرَ موجود:**

```go
	if platformCommission == 0 || repID == nil { return nil }
	if repIsBuyer { return nil }

	_, _ = repID, repIsBuyer          // ← ولا قيدَ بعدها
	return nil
```

**والقياسُ القاطع**: **`ApplyTx(..., "commission", ...)` مرّةً واحدةً في
المحرّك كلِّه — عند القيد لا عند العكس.**

## وثلاثةُ اشتراطاتٍ في عقدك يفي بها البناءُ القائم

| الشرط | أيفي به الموجود؟ |
|---|---|
| **دفتريّةٌ لا محوٌ** | ✅ **`ApplyTx` تكتب قيداً مقابلاً ولا تعدّل** — **والنمطُ مُستعمَلٌ للمتجر في السطر ١٠٨٠** |
| **قابلةٌ للتدقيق** | ✅ **`ref = orderID` و`actorID` محفوظان** |
| **رصيدٌ سالبٌ إن سُحبت** | ❌ **`CHECK (balance >= 0 OR is_treasury)` يرفض** — **فالقيدُ المقابلُ يفشل والمعاملةُ كلُّها تسقط**، **ولا يقع الاستردادُ أصلاً** |

**والثالثُ أثقلُ ممّا يبدو**: **لا يكفي إضافةُ سطرِ عكس** — **مندوبٌ سحب
عمولتَه ثمّ استُرجع الطلبُ يجعل الاسترجاعَ نفسَه مستحيلاً**، **فيُحرَم
الزبونُ مالَه بسبب رصيدِ طرفٍ ثالث.** **وعقدُك يوجب مساراً للالتزام السالب،
وهو قرارٌ في الدفتر لا سطرٌ في الدالّة.**

```
RQ-5 = CLOSED
RQ-5 CONTRACT GAPS = 2
    PG-5  لا قيدَ عكسٍ لعمولة المندوب عند الاسترداد
    PG-6  لا مسارَ التزامٍ حين تكون العمولةُ قد سُحبت — والقيدُ يُرفَض بـCHECK
```

**ولا يُمسّ دفترُ المال إلّا بقرارٍ صريحٍ منك — وهذا القرارُ صريح، والتنفيذُ
مؤجَّل.**

# `RQ-6` — **مصدرُ احتساب عمولة المندوب** · **APPROVED**

## العقد

**الإدارةُ تختار قاعدةَ الإيراد التي تُحسب منها عمولةُ المندوب** — **بلا
تعديلِ شيفرة:**

```
1 · PLATFORM_COMMISSION_ONLY
2 · PRICING_MARGIN_ONLY
3 · PLATFORM_COMMISSION + PRICING_MARGIN
```

**و`platformCommission = 0` وحدَها لا تمنع العمولةَ إن كان الوضعُ المعتمد
يسمح بالحساب من الهامش.**

## المقابلةُ بالكود

**والحالُ اليومَ خليطٌ من الوضعين الأوّل والثاني — ولا واحدٌ منهما:**

```go
// transitions.go:948 — البوّابة
if platformCommission == 0 || repID == nil { return nil }

// transitions.go:980-984 — والقاعدة
var margin int64
q.QueryRow(ctx, `SELECT `+OrderMarginSQL("$1"), orderID).Scan(&margin)
repCommission, _ := s.repShare(ctx, q, margin)   // ← الهامشُ هو الأساس
```

| ما يوجبه العقد | الحال | الحكم |
|---|---|---|
| **ثلاثةُ أوضاعٍ قابلةٌ للاختيار** | ❌ **لا مفتاحَ إطلاقاً** — **٩ مفاتيحَ في `sales.*` وليس فيها مصدرُ الحساب** | ❌ `PG-7` |
| **البوّابةُ ليست عقداً نهائيّاً** | ❌ **مُثبَّتةٌ في الشيفرة** — **ولا سبيلَ إلى تعطيلها بإعداد** | ❌ `PG-8` |
| **القاعدةُ هي الهامش** | ⚠️ **صحيحةٌ للوضع ٢** — **لكنّها محكومةٌ ببوّابة الوضع ١** | **هجينٌ لا يطابق وضعاً** |

## وما يكشفه هذا القرارُ عن السلوك القائم

**السلوكُ اليومَ ليس أيَّ واحدٍ من الأوضاع الثلاثة**: **يقيس من الهامش
(وضع ٢) ويشترط عمولةَ المنصّة (وضع ١)** — **فهو أضيقُ من كليهما**،
**ويعطي صفراً حيث يعطي الوضعان مالاً.**

**فما ظننتُه أمس «بوّابةً تحتاج قراراً» صار بقرارك خطأً في نمذجةٍ لا خياراً
تشغيليّاً** — **ووصفُه الصحيح: `CONTRACT GAP` لا `OPEN QUESTION`.**

```
RQ-6 = CLOSED
RQ-6 CONTRACT GAPS = 2   (PG-7 مفتاحُ الوضع · PG-8 بوّابةٌ مثبَّتةٌ في الشيفرة)
RQ-6 BELONGS TO = NO-CODE ADMIN CONFIGURATION
```

# `RQ-7` — **ما يراه المندوبُ من ربح المنصّة** · **APPROVED**

## العقد

```
REP SEES HIS ENTITLEMENT, NOT INTERNAL PLATFORM PROFIT
```

**يرى**: **عمولتَه · وقيمتَها ونسبتَها · والطلبَ والمتجرَ المرتبطَين ·
وحالَها.**
**ولا يرى**: **عمولةَ المنصّة الداخليّة · وهامشَ التسعير · وأرباحَها
التفصيليّة.**

## المقابلةُ بالكود — **الخرقُ في طبقتين**

| الحقل | الباب | الشاشة | الحكم |
|---|---|---|---|
| **`platform_commission`** | ✅ **يُرسَل** — `rep_merchant_detail.go:147` | ✅ **يُرسَم** — `ClientDetail.kt:252` **بعنوان «عمولة المنصة»** | **⛔ خرقٌ صريح** |
| **`forfeited_commission`** | ✅ **يُرسَل** — السطر ١٤٩ | ⚠️ **لا يُرسَم** — **والمرسومُ `forfeitedShare` وهو نصيبُه** | **⛔ خرقٌ في الباب** |
| **`my_share`** | ✅ | ✅ **«عمولتي»** | ✅ **حقُّه** |

| **`subtotal` · `total` · `delivery_fee`** | ✅ | ✅ | ✅ **ليست ربحاً داخليّاً** |
| **هامشُ التسعير** | ❌ **لا يُرسَل قطّ** | — | ✅ **مصونٌ أصلاً** |

**والنصُّ المعروضُ في الشاشة يقول ما هو بلا لبس** — `strings.xml:45`:

```xml
<string name="cd_col_commission">عمولة المنصة</string>
```

**فالمندوبُ يقرأ ربحَ المنصّة من كلّ طلبٍ بالحرف.**
**والهامشُ مصونٌ ولم يُكشَف قطّ** — **وهو نصفُ العقد قائمٌ أصلاً.**

```
RQ-7 = CLOSED
RQ-7 CONTRACT GAPS = 2
    PG-9   حقلُ platform_commission يُرسَل ويُرسَم — والحذفُ من الطبقتين
```

**وتحذيرٌ للتنفيذ لاحقاً**: **`ForfeitedShare` يُحسَب في الخادم من
`o.Commission`** (`rep_merchant_detail.go:166`) — **فحذفُ الحقل من الرسالة لا
يمسّ الحسبة، وحذفُه من الاستعلام يكسرها.** **والفرقُ بين الأمرين هو الفرقُ
بين إصلاحٍ وعطب.**

# `RQ-8` — **العمولةُ من أوّل طلبٍ مؤهَّل** · **APPROVED**

```
FIRST ELIGIBLE ORDER → REP COMMISSION ELIGIBLE
```

**ولا عتبةَ تُضيّع الطلباتِ الأولى.** **وأيُّ عتبةٍ تشغيليّةٍ مستقبلاً لا
تُلغي حقَّه في السابقات إلّا بقرارِ منتجٍ جديدٍ صريح.**

## المقابلةُ بالكود

```go
// transitions.go:1252
threshold := s.settingInt(ctx, "sales.activation_orders")
if threshold <= 1 { return true, nil }        // ← الافتراضُ ١ فالبابُ مفتوح

```

| البند | الحال | الحكم |
|---|---|---|

**فالعقدُ مُستوفىً بالافتراض ومكسورٌ بالضبط.** **ومن رفع المفتاحَ إلى ٥ ألغى
عقدَ منتجٍ معتمَداً بحقل إعدادات** — **وهذا أخطرُ من قيمةٍ خاطئة.**

**وحارسٌ سليمٌ داخلها يبقى**: **العدُّ يستثني شراءَ المندوب نفسِه**
(`o.customer_id IS DISTINCT FROM m.sales_rep_user_id`) — **فلا يُفعّل متجرَه
بشرائه منه.**

