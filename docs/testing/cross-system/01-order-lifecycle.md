# ٢ · الطلبُ العاديّ — من الإنشاء إلى التسوية

## المسارُ المقيس

```
الزبون: تصفّح ← صنف ← سلّة ← عنوان ← إتمام
   │
   └─ POST /orders  (محميٌّ بمفتاح تكرار)
        ├─ checkOpenLimit          ← داخلَ بوّابة واتساب (D4)
        ├─ cashBlocked             ← يُنادى
        ├─ INSERT orders
        ├─ INSERT order_events ''→pending
        ├─ publishOrder ×3         ← ops · merchant: · customer:
        ├─ notifyCreated           ← المتجرُ (عددُ الأصناف والمبلغ) · والمكتب
        └─ [وضعُ المتاجر] AutoDispatch ← واتساب إلى المتجر
   │
المتجر: يقبل / يُرفض / تمرّ المهلةُ فيَقبل النظام
   │
   ├─ accepted → preparing
   │
الإسناد: دورٌ أو اختيارٌ إداريّ
   ├─ عرضٌ لسائقٍ بمهلة (offer_expires_at)
   ├─ SweepExpiredOffers ← ينقل العرضَ لمن يليه
   └─ قبولُ السائق → assigned
   │
   at_pickup → picked_up → on_the_way → at_dropoff → delivered
   │
   └─ التسوية (settle):
        ├─ merchant_earning   لكلّ مطبخ
        ├─ driver_earning
        ├─ settleRep          ← عمولةُ المندوب
        ├─ creditTreasury
        └─ notifyTransition + notifyCommission + notifyCredits
```

## أثرُ كلّ طرفٍ عند التسليم

| الطرف | ما يقع |
|---|---|
| **الزبون** | **الحالُ `delivered`** · **إشعارٌ موجَّهٌ لتطبيقه** · **بثٌّ في غرفته** |
| **المتجر** | **`merchant_earning` في محفظته** · **إشعارٌ موجَّه** · **بثٌّ بالطلب كاملاً** ⚠️ `XG-1` |
| **السائق** | **`driver_earning`** · **والنقدُ في صندوقه إن كان نقديّاً** |
| **المندوب** | **`commission` إن كان للمتجر مندوبٌ ومرّت العتبة والبوّابة** |
| **المنصّة** | **`platform_commission` لقطةً في الطلب** · **والخزينةُ تُقيَّد** |
| **الإدارة** | **بثٌّ في `ops`** · **والتقاريرُ تقرأ من الطلبات والدفتر** |
| **التدقيق** | **`ops.order_transition`** — **غيرُ متزامنٍ** ⚠️ `XG-20` |

## نقاطُ الانكسارِ الجزئيّ في هذا المسار

| النقطة | ما يقع |
|---|---|
| **بعد `INSERT orders` وقبل الردّ** | **`R8`** — **الطلبُ قائمٌ والزبونُ لا يعلم** |
| **`AutoDispatch` بعد القبول** | **`R21`** — **مقبولٌ والمتجرُ لا يعلم** |
| **قبولُ السائق** | **`R7`** — **٣ كتاباتٍ بلا معاملة** |
| **التسوية** | **معاملةٌ واحدة** ✅ — **وهو أنظفُ ما في المسار** |
| **الإشعارُ بعد التسوية** | **`R23`** — **فشلُ الدفع بلا أثر** |

# ٤ · الردُّ الضائع عند الإنشاء

## دورةُ حياةِ المفتاح — مُقاسة

```go
// server/idempotency.go
idempotencyTTL = 24 * time.Hour

claimIdempotency:
    DELETE FROM idempotency_keys WHERE created_at < now() - '24h'   ← بلا شرطِ done
    INSERT ... ON CONFLICT DO NOTHING                                ← الظفرُ للأوّل

بعد المعالج:
    status >= 400  → releaseIdempotency (حذفٌ فوريّ)
    status <  400  → storeIdempotency  (done = true + الردُّ محفوظ)

عند مفتاحٍ مكرَّر:
    done = true   → يُعاد الردُّ المحفوظُ نفسُه + ترويسة Idempotent-Replay
    done = false  → 409 in_progress
```

| السؤال | الجواب المقيس |
|---|---|
| **أين يُخزَّن؟** | **بوستغرس** — `idempotency_keys` (`0103`) · **لا Redis** |
| **أثمّة مهلة؟** | **٢٤ ساعة** |
| **أتسري على `in_progress`؟** | **نعم** — **التقليمُ بلا `WHERE done = false`** |
| **أثمّة مسارُ إزالة؟** | **مساران** — **الفشلُ يحرّر فوراً · والتقليمُ يمسح بعد ٢٤ ساعة** |
| **متى ينتهي الـ٤٠٩؟** | **عند أوّل نداءٍ لأيّ بابٍ محميٍّ من أيّ مستخدمٍ بعد ٢٤ ساعة** |
| **كيف يعرف الزبونُ الحقيقة؟** | **`GET /my/orders`** — **ولا مسارَ «استعلمْ عن مفتاحي»** |
| **ماذا لو أعاد بمفتاحٍ جديد؟** | **⚠️ طلبٌ ثانٍ** — **والمفتاحُ من العميل** |
| **ماذا ترى الإدارة؟** | **طلبين في القائمة** — **ولا علامةَ تربطهما** |

**و`R8` مؤكَّدٌ كما هو في السجلّ المجمَّد.**

# ٥ · قبولُ المتجر

| الحالة | الزبون | إرسالُ السائق | الإشعار | البثّ | حدثٌ | تدقيق |
|---|---|---|---|---|---|---|
| **قبولٌ يدويّ** | ✅ يُخطَر | ✅ يبدأ | ✅ للزبون | ✅ ثلاثُ غرف | ✅ | ✅ |
| **قبولٌ تلقائيّ** | ✅ يُخطَر | ✅ يبدأ | **❌ للمتجر** | ✅ | ✅ | **⚠️ `ops` لا `audit_log`** |

## `MD-5` — **القبولُ التلقائيُّ صامتٌ**

```go
// orders/watchdog.go:224
s.logger.Info("قُبل تلقائيّاً بعد المهلة", "order", id, "minutes", mins)
```

**سطرُ سجلٍّ للخادم — والمتجرُ لا يعلم أنّ التزاماً وقع عليه ومهلةَ التحضير
تعدّ.**

**وتعليقُ الدالّة يَعِد بعكس ما تفعل**: «**فيمضي الطلبُ كما لو ضغطه موظّف:
يُخطَر المتجرُ**» — **و`notifyTransition` لا تعرف إلّا `customerTitles`.**

## `MD-2` — **لا إشعارَ عند الإسناد ولا عند الوصول**

**المتجرُ يُشعَر في موضعين من أربعةَ عشرَ**: **طلبٌ جديد** · **تمّ التسليم.**

## `R21` · `D19` — **حين تسقط القناتان**

**واتساب يفشل بعد القبول ⇒ لا إبلاغ.**
**والبثُّ يعيد الوصلَ بتوكنٍ منتهٍ ⇒ لا بديل.**
**فالطلبُ مقبولٌ ولا أحدَ في المتجر يعلم** — **وهو `RV-M1`.**

# ٦ · إسنادُ السائق وقبولُه

```
سائقون متاحون (ورديّةٌ + سقفٌ + نقدٌ)
   → عرضٌ بمهلة (offer_expires_at)
   → بثٌّ في driver:<id> + topicDriverQueue
   → إشعارٌ موجَّهٌ (AppDriver) ✅
   → قبولٌ  → assigned
   → أو انقضاءٌ → SweepExpiredOffers → التالي
```

| الحارس | الموضع | الخطر |
|---|---|---|
| **`max_active`** | يُقرأ ثمّ يُكتب | **`R10`** |
| **سقفُ النقد** | `driver_handlers.go:578` | **`D7`** — **يقيس المحصَّل لا المكشوف** |
| **الورديّة** | ✅ | — |
| **الطريقُ نفسُه** | `sameroute.go` | §٧ |

**و`R7`**: **٣ كتاباتٍ بلا معاملةٍ عند القبول** — **وانقطاعُ السياق يترك حالةً
بلا حدث، فالخطُّ الزمنيُّ في اللوحة ناقص.**

**و`D1`**: **فكُّ الإسناد بلا حدثٍ** — **فالإدارةُ ترى سائقاً اختفى بلا سطر.**
