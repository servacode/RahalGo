# ٢١ · مصدرُ المال ← الدفتر ← الرصيد ← الخزينة

## البنيةُ المقيسة

```sql
-- 0010_wallets.sql
wallets(user_id PK, balance bigint CHECK (balance >= 0), updated_at)
wallet_transactions(id, user_id, amount CHECK (amount <> 0), kind, ref, note, actor)
```

**رقمٌ واحدٌ لا طبقات** — **ولا `available` ولا `reserved` ولا `obligation`.**

## أنواعُ القيد وأصحابُها

| النوع | من ← إلى | متى |
|---|---|---|
| `order_payment` | الزبون ← الخزينة | **دفعٌ بالمحفظة** |
| `merchant_earning` | الخزينة ← المتجر | **التسليم** |
| `driver_earning` | الخزينة ← السائق | **التسليم** |
| `commission` | الخزينة ← المندوب | **التسليم** · **وبلوغُ هدف** |
| `refund` | الخزينة ← الزبون | **الاسترداد** |
| `compensation` | الخزينة ← السائق | **قرارٌ إداريّ** |
| `payout` | صاحبُه ← خارجَ المنصّة | **قرارُ صرف** |
| `adjustment` | الخزينة ↔ أيّ طرف | **تصحيحٌ إداريّ** |
| `topup` | الخزينة ← الزبون | **قيدٌ إداريّ** — **ولا شحنَ خارجيّاً بعد** |

## الثوابتُ المحروسة

**`cmd/moneycheck` — ١٣ فحصاً.**
**والمعادلةُ المركزيّة**: `delta = (paid − refunded − toParties) − posted`.

**وما لا يحرسه**:

| البند | الحال |
|---|---|
| **المصاريف** | ❌ **صفرُ ذكرٍ لـ`expenses`** — **`TIG-3`** · **وهو البابُ الذي دخل منه `D5`** |
| **قناةُ دفعٍ خارجيّة** | ❌ **لم تُبنَ** — **وشام كاش ستحتاجها** |
| **عكسُ عمولة المندوب** | ❌ **لا فعلَ فلا ثابت** |

# ١٤ · الاستردادُ من طرفٍ إلى طرف

## ما يقع فعلاً — `reverseCommissions` (`transitions.go:1010-1098`)

| الطرف | الأثر |
|---|---|
| **الزبون** | ✅ **`refund` بالمبلغ** |
| **المتجر** | ✅ **`ApplyTx(-amount, "merchant_earning")` لكلّ مطبخٍ قبض** |
| **المنصّة** | ✅ **`UPDATE orders SET platform_commission = 0`** |
| **السائق** | ⚠️ **أجرُه لا يُعكَس** — **وهو قرارٌ صحيحٌ ظاهراً: أوصل فعلاً** |
| **المندوب** | ❌ **لا شيء** |

## والحرّاسُ الثلاثةُ يحرسون فعلاً غيرَ موجود

```go
	if platformCommission == 0 || repID == nil { return nil }
	if repIsBuyer { return nil }

	_, _ = repID, repIsBuyer          // ← ولا قيدَ بعدها
	return nil
```

**والقياسُ القاطع**: **`ApplyTx(..., "commission", ...)` مرّةً واحدةً في
المحرّك كلِّه** — **عند القيد لا عند العكس.**

**والتعليقُ فوق الدالّة يَعِد بعكسها نصّاً** — **فالشيفرةُ تناقض وثيقتَها.**

## و`RQ-5` + `AQ-3` — **العقدُ وما يمنعه**

| ما يوجبه العقد | ما يمنعه |
|---|---|
| **الاستردادُ لا يفشل أبداً** | **`CHECK (balance >= 0)` يرفض القيدَ المقابل ⇒ تسقط المعاملةُ كلُّها** |
| **التزامٌ سالبٌ يُسجَّل** | **لا جدولَ ولا نوعَ قيدٍ للالتزام** — **و`kind` قائمةٌ مغلقة** |
| **السببُ والطلبُ والوقتُ والمصدر** | ⚠️ **`ref` و`note` و`actor` موجودة** — **والمفهومُ غائب** |
| **السدادُ من العمولات اللاحقة** | ❌ **لا آليّة** |
| **`AVAILABLE`/`RESERVED`/`OUTSTANDING`** | ❌ **طبقةٌ واحدة** |

**وقرارُك حسم الاتّجاه**: **لا يُفتح `CHECK`** — **بل تُضاف طبقةٌ ثالثة.**
**وهذا يحمي حارساً سليماً**: **`CHECK` هو ما يمنع سحبَ ما ليس في المحفظة.**

## السلسلةُ الكاملةُ للخطر

```
مندوبٌ قبض عمولةً  →  سحبها  →  الرصيدُ صفر
   →  الزبونُ يطلب استرداداً
   →  reverseCommissions لا تحاول عكسَها أصلاً (اليوم)
   →  فالاستردادُ يمضي والمالُ يخرج مرّتين
```

**وإن بُني العكسُ بلا طبقةِ التزام:**

```
   →  ApplyTx(-25,000) على رصيدٍ صفر
   →  CHECK يرفض  →  المعاملةُ تسقط
   →  الزبونُ لا يُستردّ له
```

**فالعقدُ يحتاج البنيتين معاً** — **العكسَ والالتزام.**

# ١٥ · عمولةُ المندوب من طرفٍ إلى طرف

```
متجرٌ لمندوبٍ  →  طلبٌ مؤهَّل  →  delivered
   →  settleRep:
        platformCommission == 0 ?  →  لا شيء            ← XG-14
        repIsBuyer ?               →  لا شيء            ← ✅ حارسٌ سليم
        merchantActivated ?        →  عتبةٌ لم تبلغ ⇒ لا شيء ← XG-15
        margin = Σ (unit_price − merchant_price) × qty
        repCommission = margin × sales.commission_percent
        ApplyTx(+repCommission, "commission", orderID)
        notifyCommission ✅ موجَّه
```

| القرار | الحال |
|---|---|
| **`RQ-6`** ثلاثةُ أوضاعٍ للمصدر | ❌ **لا مفتاح** — **والسلوكُ هجينٌ لا يطابق وضعاً** |
| **`RQ-8`** من أوّل طلبٍ مؤهَّل | ⚠️ **مستوفىً بالافتراض `1`** · **ومكسورٌ بالضبط** |
| **`RQ-7`** يرى استحقاقَه لا ربحَ المنصّة | ❌ **`platform_commission` يُرسَل ويُرسَم** |
| **`RQ-5`** يُعكَس عند الاسترداد | ❌ |
| **`RQ-2`** الماضي للقديم واللاحقُ للجديد | ✅ **مضمونٌ بنيويّاً** · ❌ **بلا سجلّ** |

**والافتراضاتُ الثلاثةُ صفر** — `merchants.commission_percent` ·
`sales.commission_percent` · `pricing.margin_fixed`. **فمن نصّب المنصّةَ ولم
يضبط شيئاً: المندوبُ يعمل ولا يكسب، ولوحتُه تعرض صفراً بلا تفسير.**

# ١٦ · ملكيّةُ المتجر ونقلُها

```
المندوبُ (أ) يسجّل  →  merchant_leads.sales_rep_user_id = أ
   →  الأدمنُ يحوّل  →  convertLead
        └─ CreateMerchant(SalesRepCode = invite_code(أ))
              →  merchants.sales_rep_user_id = أ
   →  الأدمنُ ينقل  →  PATCH /admin/merchants/{id}
        →  merchants.sales_rep_user_id = ب
```

| السؤال | الجواب |
|---|---|
| **العمولاتُ السابقة** | ✅ **قيودٌ باسم (أ) لا تُمسّ** — **والدفترُ لا يُعدَّل** |
| **العمولاتُ اللاحقة** | ✅ **لـ(ب) من أوّل تسليمٍ بعد النقل** — **`settleRep` تقرأ العمودَ لحظتَها** |
| **الأثرُ التدقيقيّ** | ❌ **`admin.merchant_update` عامٌّ** — **ولا سطرَ يقول «نُقل من أ إلى ب»** — `XG-17` |
| **التاريخ** | ❌ **لا جدول** — **والأثرُ الوحيدُ `merchant_leads` يحفظ أوّلَ من جلبه** |

## والتكرارُ — **أربعُ طبقاتٍ بلا حارس**

| الطبقة | حارس |
|---|---|
| `POST /rep/leads` | ❌ |
| جدولُ `merchant_leads` | ❌ **لا قيدَ فريد** |
| `CreateMerchant` | ❌ |
| جدولُ `merchants` (`phone`) | ❌ **فهرسٌ لا قيد** |
| `convertLead` (`merchant_id != nil`) | ✅ **يمنع تحويلَ المرشَّح نفسِه مرّتين** — **ولا يرى مرشَّحاً ثانياً** |

**والأثر**: **متجران في السوق · صاحبٌ واحدٌ (`resolveOwner` يربط الرقمَ نفسَه)
· ومندوبان يقبضان.**
**والفوزُ لمن يُحوَّل أوّلاً لا لمن سجّل أوّلاً** — **وهو نقيضُ `RQ-3`.**

**و`D2` يزيدها**: **إن فشلت الخطوةُ السابعة بقي المرشَّحُ `new` والمتجرُ
مُنشأً** — **فيُعاد التحويلُ فيُنشأ متجرٌ ثانٍ**، **والحارسُ الوحيدُ معطَّلٌ في
الحالة التي وُضع لها.**

# ٢٢ · السحبُ اليومَ وغداً

## اليوم

```
طلبٌ  →  POST /me/payouts
   ├─ دورٌ في payoutRoles (sales · driver · merchant)
   ├─ amount ≤ balance  ·  ≥ payouts.min_amount أو = الرصيد
   ├─ INSERT payout_requests   ← ولا يُخصَم شيء
   └─ NotifyRoles(admin, finance)

قرارٌ  →  POST /admin/payouts/{id}/decide   (idempotent)
   ├─ SELECT ... FOR UPDATE
   ├─ status = paid  →  ApplyTx(-amount, "payout")
   ├─ UPDATE payout_requests
   ├─ COMMIT
   ├─ audit finance.payout_decide
   └─ إشعارٌ لصاحبه (بلا توجيهِ تطبيق ⚠️)
```

**وهو أنظفُ مسارٍ ماليٍّ قِيس** — **معاملةٌ وقفلُ صفٍّ ولفٌّ `idempotent`
وتدقيقٌ وفهرسٌ فريدٌ يمنع طلبين معلّقين.**

## والفجوةُ مقابل عقد شام كاش

| الحالُ المطلوب | الحال |
|---|---|
| `AVAILABLE` | ⚠️ **الرصيدُ كلُّه** |
| `RESERVED` | ❌ **الطلبُ لا يحجز** |
| `PENDING` | ✅ `pending` |
| `PROCESSING` | ❌ |
| `COMPLETED` | ✅ `paid` |
| `FAILED` | ⚠️ `rejected` — **قرارٌ لا فشلٌ تقنيّ** |
| `REVERSED` | ❌ |

**والخطرُ الكامنُ اليوم**: **الطلبُ لا يحجز** — **فالمندوبُ يطلب سحبَ كلّ
رصيده، ثمّ تُقيَّد له عمولة، ثمّ يُصرَف الطلبُ القديمُ بمبلغه القديم.**
**ولا خطأَ يقع — لكنّ الأرقامَ لا تعني ما يظنّه قارئُها.**

# ٢٣ · شام كاش — تدفّقاتٌ مستقبليّة

**`EXTERNAL CONNECTOR = PENDING PROVIDER DETAILS`** — **ولم أخترع باباً.**

## دفعُ الطلب — `XPRQ-PAY-01`

```
الزبون  →  المزوّد  →  تحقّق  →  PaymentAttempt  →  حالُ دفع الطلب  →  مسارُ الطلب
```

| ما يلزم | الحال |
|---|---|
| جدولُ محاولاتٍ | ❌ |
| حالُ دفعٍ في الطلب | ⚠️ **`PaymentMethod` نصّ** |
| **تحقّقٌ خادميٌّ لا ثقةٌ بالعميل** | ❌ |
| **ربطٌ بمفتاح تكرار** | ⚠️ **`R8` يمسّ نقطةَ الدفع** |

## شحنُ المحفظة — `XPRQ-PAY-02`

```
المستخدم  →  المزوّد  →  تحقّق  →  قيدٌ مرّةً واحدةً بالضبط
```

**و«مرّةً واحدةً بالضبط» هي المطلبُ الأصعب** — **ولا صندوقَ ولا مفتاحَ
خارجيٌّ اليوم.**

## السحب — `XPRQ-PAY-03`

```
طلبٌ  →  حجزٌ  →  المزوّد  →  تأكيد  →  تسويةٌ أو إطلاق
```

**والحجزُ غيرُ موجود** — **وهو أوّلُ ما يلزم** (`XG-12`).

## الحسابُ المربوط — `XPRQ-PAY-04`

```
المستخدم  →  إثباتُ الملكيّة  →  تبديلٌ حسّاس  →  مصادقةٌ ثانيةٌ + تدقيقٌ + إشعار
```

| ما يلزم | الحال |
|---|---|
| حقلٌ للحساب | ❌ |
| إثباتُ ملكيّة | ❌ |
| **مصادقةٌ ثانيةٌ للتبديل** | ❌ **لا شيء في المنصّة كلِّها** — `AS-3` |
| تدقيقٌ متزامن | ❌ **`AQ-4`** |

```
REP/MERCHANT/DRIVER SHAM CASH GAPS = 5 لكلّ دور
SHAM CASH ADMIN GAPS = 5
```
