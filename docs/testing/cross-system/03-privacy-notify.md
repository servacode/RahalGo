# ١١ · الخصوصيّةُ عبر الأطراف

## ثلاثةُ حرّاسٍ — وموضعُهم كلُّهم في طبقة `server`

```
server/customer_privacy.go   → redactForCustomer   (4 حقول)
server/merchant_privacy.go   → redactForMerchant   (16 حقلاً)
                              ولا حارسَ للسائق — ما يصله هو الطلبُ كاملاً
```

## ما يمحوه كلُّ حارس — **مقيسٌ سطراً بسطر**

| الحقل | للزبون | للمتجر |
|---|---|---|
| `MerchantID` · `MerchantName` · `MerchantLogoThumb` | ❌ **يُمحى** | — |
| `OfferedDriverName` | ❌ **يُمحى** | ❌ **يُمحى** |
| `CustomerID` · `CustomerName` · `CustomerPhone` | — | ❌ **يُمحى** |
| `AddressText` · `Lat` · `Lng` · `ZoneID` · `ZoneName` | — | ❌ **يُمحى** |
| `DriverID` · `DriverName` | — | ❌ **يُمحى** |
| **`DriverPhone`** | **✅ يصل** ⚠️ | ❌ **يُمحى** |
| `ProofURL` · `ProofTakenAt` · `ProofMeters` | — | ❌ **يُمحى** |
| المبالغُ كلُّها · `PaymentMethod` · `PromoCode` | — | ❌ **تُمحى** |

## ⚠️ `XOB-2` — **الحقلُ نفسُه محميٌّ هنا ومكشوفٌ هناك**

**العقدُ**: «**الزبون: لا يرى driver phone**».
**والمتجرُ يُمنع منه صراحةً بسطرٍ مكتوب** — **والزبونُ يصله.**
**فليس سهواً في الحارسين معاً، بل قرارٌ اتُّخذ لأحدهما ونُسي في الآخر.**

## ⚠️ `XOB-1` — **والقناةُ الحيّةُ تتجاوز الحرّاسَ كلَّهم**

```go
// orders/service.go:114-131
event := map[string]any{"type": "order", "order": o}
s.pub.Publish("ops",                  event)
s.pub.Publish("merchant:"+o.MerchantID, event)   // ← الطلبُ كاملاً بلا تنقية

cust := *o
cust.MerchantID, cust.MerchantName, cust.MerchantLogoThumb = "", "", nil
s.pub.Publish("customer:"+o.CustomerID, ...)     // ← ثلاثةُ حقولٍ فقط

if o.DriverID != nil { s.pub.Publish("driver:"+*o.DriverID, event) }
```

**والنفيُ مقيسٌ صراحةً**: `grep redact internal/orders/` **يردّ صفراً.**

| الطرف | REST | البثُّ الحيّ | الفرق |
|---|---|---|---|
| **المتجر** | **١٦ حقلاً تُمحى** | **لا شيء** | **هاتفُ الزبون · عنوانُه · نقطتُه · هاتفُ السائق · إثباتُ التسليم · المبالغ** |
| **الزبون** | **٤ حقولٍ تُمحى** | **٣** | **`OfferedDriverName`** |
| **السائق** | **لا حارس** | **لا حارس** | — |

**فالمتجرُ يقرأ في القناة الحيّة نقطةَ الزبون على الخريطة** — **وهي بعينُها
ما مُنع منها في الباب.**

## وما يراه السائق

**الطلبُ كاملاً** — **اسمُ الزبون وعنوانُه وتعليماتُه** ✅ **مطلوب** ·
**وهاتفُه** ⚠️ **يصل في النموذج** (`CustomerPhone`) — **والعقدُ يقول لا
يراه.** **ولا حارسَ للسائق إطلاقاً**، فالمنعُ إن وقع فهو في الواجهة لا في
الباب.

# ١٢ · الروابطُ العميقة

## الحقيقةُ الواحدةُ للأربعة

```kotlin
// mobile/ui/.../push/RahalPushService.kt:115
val open = PendingIntent.getActivity(
    this, 0,
    Intent(this, home()).addFlags(Intent.FLAG_ACTIVITY_CLEAR_TOP),
    ...)
```

**كلُّ إشعارٍ يفتح الشاشةَ الأولى** — **في التطبيقات الأربعة.**

| ما يُرسله المحرّك | أيُقرأ في الجهاز؟ |
|---|---|
| `Entity` (`order` · `wallet` · `lead` · `ticket` · `payout`) | ❌ |
| `EntityID` | ❌ |
| `Href` (`/portal/orders` · `/dashboard/...`) | ❌ **مسارُ ويبٍ لا مسارُ تطبيق** |

**فالبنيةُ كاملةٌ في الخادم ومقطوعةٌ في الجهاز.**
**وهي `PC-4` و`MG-5` و`XG-8`** — **مشتركةٌ في `:ui` تُصلَح مرّةً واحدة.**

# ١٣ · انتهاءُ التوكن واستمرارُ البثّ

| الطبقة | السلوكُ المقيس |
|---|---|
| **REST** | ✅ **تجديدٌ تلقائيّ** — **إلّا في الرفع** (`R18`) |
| **البثّ** | ❌ **`LiveSocket` يعيد الوصلَ بتوكنٍ منتهٍ** — `D19` |
| **المصافحة** | ❌ **لا مراجعةَ بعدها** — `R14` |
| **الإبطال** | ⚠️ **Redis تفشل مفتوحةً** — `R16` |
| **الدفع** | ⚠️ **الرمزُ يبقى بعد الخروج** — `D12` |

**والأثرُ عبر التطبيقات**:

| التطبيق | ماذا يفقد بصمت |
|---|---|
| **المتجر** | **طلباً جديداً** — **`D19` مسجَّلٌ فيه نصّاً** |
| **الزبون** | **تقدّمَ طلبه** |
| **المندوب** | **قبولَ عميله** |
| **السائق** | ⚠️ **عرضاً على الطريق** — **والقناةُ هي ناقلُه** |

**و`ws.go:149` فيه نبضةٌ كلَّ ٣٠ ثانية** — **تُبقي الوصلةَ حيّةً ولا تراجع
صلاحيّتَها.** **فوصلةٌ قامت بتوكنٍ صالحٍ تبقى إلى الأبد** (`R14`).

# ٢٩ · فشلُ واتساب

**المسارُ**: `AutoDispatch` → `Ready()` → `SendText`.

| السؤال | الجواب |
|---|---|
| **أيبقى الطلبُ مقبولاً؟** | ✅ **نعم** — **الحالُ لا يرتدّ** |
| **أيعلم المتجر؟** | ❌ **لا** — **إلّا إن كانت قناتُه الحيّةُ سليمة** |
| **أيعلم الزبون؟** | ❌ **لا** — **يرى «قيد التحضير»** |
| **أثمّة إعادة؟** | ❌ **لا** |
| **أترى الإدارةُ الفشل؟** | ❌ **لا سطحَ** — **و`R24`: نمطان من سبعةٍ يُقرآن** |
| **أيعوّض البثّ؟** | ⚠️ **إن كان حيّاً** — **و`D19` يقطعه بصمت** |
| **وإن سقط الاثنان؟** | **الطلبُ مقبولٌ ولا أحدَ في المتجر يعلم** |

**والمعالجةُ اليدويّةُ قائمة**: `POST /admin/orders/{id}/whatsapp` — **مُدقَّقةٌ
بـ`ops.order_notify`.** **لكنّ الإدارةَ لا تعلم أنّها لازمة.**

# ٣٠ · فشلُ الدفع

| السؤال | الجواب |
|---|---|
| **أثمّة إعادة؟** | ❌ |
| **أثمّة صندوقُ إرسال؟** | ❌ **`R23`** — **«الصندوقُ هو الحقيقة»** |
| **أتُحفَظ الحال؟** | ❌ **لا `notification_deliveries`** |
| **أتراه الإدارة؟** | ❌ |
| **أتُعدّ العمليّةُ ناجحة؟** | ✅ **نعم** — **الإشعارُ لا يُفشل الفعل** |

**والصفُّ في `notifications` يبقى** — **فالمستخدمُ يراه إن فتح صندوقَه.**
**فالخسارةُ في الرنّة لا في السجلّ** — **وهذا يخفّف `R23` ولا يلغيه**:
**السائقُ الذي لم ترنّ له لا يفتح صندوقاً.**
