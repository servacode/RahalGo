# صفر · مصالحةُ `R8` — **قبل أيّ إعلان**

**وصفتُ الحالَ في وثيقة الإغلاق بأنّه «٤٠٩ إلى الأبد ولا سطحَ يمسحه».**
**والسجلُّ المجمَّد يقول «~٢٤ ساعة».** **فقستُ التنفيذ.**

## أين يُخزَّن؟

**في بوستغرس لا في Redis** — جدولُ `idempotency_keys` (`0103_idempotency.sql:32`)
بأعمدة `user_id` · `endpoint` · `key` · `done` · `status_code` · `response` ·
`created_at`، **وفهرسٌ على `created_at`** (السطر ٥٩).

**فإعادةُ تشغيل Redis وسلوكُها لا يمسّانه إطلاقاً** — **وهذا يُسقط أحدَ
أسئلتك من أساسه.**

## أله مهلة؟ وهل تسري على `in_progress`؟

**نعم — والتقليمُ بلا شرطِ `done`:**

```go
// idempotency.go:20
idempotencyTTL = 24 * time.Hour

// idempotency.go:79-82 — داخلَ claimIdempotency
if _, err := s.pg.Exec(ctx,
    `DELETE FROM idempotency_keys WHERE created_at < now() - $1::interval`,
    idempotencyTTL.String()); err != nil {
```

**ولا `WHERE done = false` ولا `WHERE user_id = ...`** — **فالحذفُ يشمل
العالقَ كما يشمل المكتمل، ولكلّ المستخدمين.**

## أثمّة مسارٌ يزيل المفتاح؟

**مساران:**

| المسار | متى |
|---|---|
| **`releaseIdempotency`** | **حين يردّ المعالجُ `>= 400`** — **يحذف الصفَّ فوراً** (`done = false`) |
| **التقليمُ في `claimIdempotency`** | **عند أوّل نداءٍ لأيّ بابٍ محميٍّ بعد مضيّ ٢٤ ساعة** |

## متى ينتهي الـ٤٠٩ فعلاً؟

**عند أوّل نداءٍ لأيّ بابٍ من الستّة المحميّة — من أيّ مستخدم — بعد مضيّ
٢٤ ساعةٍ على `created_at`.**

**والتقليمُ كسولٌ لا مجدوَل**: **لا يقع إن لم يُنادَ بابٌ محميّ.**
**والأبوابُ الستّة**: **إنشاءُ طلبٍ للزبون** · **طلبٌ خاصّ** · **قيدُ محفظة** ·
**منحُ حافز** · **قرارُ سحب** · **تسويةُ سائق** — **وأوّلُها يُنادى عشراتِ
المرّات يوميّاً.**

## الحكم

```
R8 FROZEN DESCRIPTION CONFIRMED
```

**والسجلُّ المجمَّد دقيقٌ ووصفي في وثيقة الإغلاق خاطئ.**
**«٤٠٩ إلى الأبد» غيرُ صحيح — الصوابُ «حتّى ٢٤ ساعة».**
**والنصفُ الثاني صحيحٌ ولا معنى له**: **لا سطحَ إداريّاً يمسحه — ولا يحتاج
إليه، فالمهلةُ تكفيه.**

**وصُحّح الوصفُ في** [`ADMIN_PANEL_CLOSURE.md`](ADMIN_PANEL_CLOSURE.md)
**§٢٠ و§٢٧** — **ولم يُمسّ السجلُّ المجمَّد.**

**والخطأُ خطئي**: **قرأتُ أثرَ الحالة العالقة ولم أقرأ `claimIdempotency`.**

# `AQ-2` — **نموذجُ الفروع** · **APPROVED**

## العقد

```
GEOGRAPHY != OPERATIONAL BRANCH
```

**والهرمُ**: **محافظة → مدينة → فرعُ المدينة الرئيسيّ → مناطقُ تشغيل.**
**والمناطقُ افتراضاً `OPERATIONAL AREAS` لا فروعاً** — **وتُرقّى إلى
`SUB-BRANCH` عند حاجةٍ تشغيليّةٍ حقيقيّة.**
**والنظامُ يدعم لاحقاً**: **أكثرَ من فرعٍ في مدينة · وفروعاً فرعيّةً ·
ومناطقَ مرتبطةً بفرع · وسائقين ومتاجرَ ومندوبين وطلباتٍ ودعماً وتقاريرَ لكلّ
فرع.**

## المقابلةُ بالكود

```
CREATE TABLE branches  →  غير موجود
```

**ولا جدولَ ولا عمودَ ولا مفهومَ فرعٍ في المخطّط كلِّه.**

## ⚠️ والهرمُ القائم مقلوبٌ عن المطلوب

| المطلوب | القائم |
|---|---|
| **محافظة → مدينة → مناطقُ تشغيل** | **محافظة → ناحية → مدينة** |

**والدليلُ عمودٌ واحد** (`0122_governorates_districts.sql:100`):

```sql
ALTER TABLE cities ADD COLUMN IF NOT EXISTS district_id uuid REFERENCES districts(id);
```

**فالمدينةُ تتبع الناحيةَ في الكود** — **والعقدُ يجعل المنطقةَ تحتَ المدينة.**
**وهذا ليس فرقاً في التسمية بل في اتّجاه المفتاح الأجنبيّ**، **ويقلب كلَّ
استعلامِ تجميعٍ بالفرع.**

**ولا أسمّيه خطأً**: **`districts` بُنيت لعنوان المتجر لا لتنظيم العمليّات**
— **وهي صحيحةٌ لغرضها، وغيرُ صالحةٍ لهذا الغرض كما هي.**

## والقرارُ يحسم سؤالاً كنتُ سأسأله

**سألتُ في `AQ-2`: أتصير `cities` هي الفرعَ بعد توسيعها؟**
**والجوابُ لا** — **`GEOGRAPHY != OPERATIONAL BRANCH`.**
**فـ`cities` تبقى جغرافيا، والفرعُ كيانٌ جديدٌ يشير إليها.**

```

BRANCH MODEL GAPS = 10   (٩ سابقةً + ADG-5 انقلابُ الهرم)
AQ-2 CONTRACT GAPS = 3   (ADG-4 لا كيانَ فرع · ADG-5 هرمٌ مقلوب · ADG-6 لا ربطَ مواردَ ولا تقريرَ بالفرع)
XPRQ-BRANCH = مطلبُ منظومةٍ معتمد
```

# `AQ-3` — **الالتزامُ السالبُ للمندوب بعد الاسترداد** · **APPROVED**

## العقد

**استردادُ الزبون لا يفشل أبداً بسبب رصيد المندوب.**
**ويُسجَّل على المندوب التزامٌ بقيمة العمولة الواجبِ عكسُها.**

```
REP COMMISSION = +25,000
REP WITHDRAWS  = 25,000
ORDER REFUNDED
REP OBLIGATION = -25,000
```

**ويُحفَظ**: **المبلغُ · والسببُ · والطلبُ المرتبط · والوقتُ · والمصدرُ ·
ومرجعُ الدفتر والتدقيق.**
**والعمولاتُ اللاحقةُ تُسدّد الالتزامَ أوّلاً**، **وبعد بلوغه صفراً يعود
الرصيدُ القابلُ للسحب.**

**ولا رصيدَ سالبٍ عشوائيّ إن كان الأنسبُ فصلَ**:
`AVAILABLE` · `RESERVED` · `OUTSTANDING OBLIGATION`.

## المقابلةُ بالكود

```sql
-- 0010_wallets.sql:5-7
CREATE TABLE wallets (
    user_id uuid PRIMARY KEY ...,
    balance bigint NOT NULL DEFAULT 0 CHECK (balance >= 0),   -- ل.س — لا سالب أبداً
    updated_at timestamptz NOT NULL DEFAULT now()
);
```

| ما يوجبه العقد | الحال | الحكم |
|---|---|---|
| **الاستردادُ لا يفشل** | ❌ **يفشل** — **`CHECK` يرفض القيدَ المقابل فتسقط المعاملةُ كلُّها** | ❌ `FC-3` |
| **سجلُّ التزام** | ❌ **لا جدولَ ولا نوعَ قيدٍ للالتزام** — **و`kind` قائمةٌ مغلقة** | ❌ `ADG-8` |
| **السببُ والطلبُ والوقتُ والمصدر** | ⚠️ **`wallet_transactions` تحمل `ref` و`note` و`actor`** — **فالحقولُ موجودةٌ والمفهومُ غائب** | **جزئيّ** |
| **`AVAILABLE`** | ❌ **رقمٌ واحدٌ لا طبقات** | ❌ `ADG-7` |
| **`RESERVED`** | ❌ **طلبُ السحب لا يحجز شيئاً** | ❌ `FC-1` |
| **`OUTSTANDING`** | ❌ **لا وجودَ له** | ❌ `ADG-8` |
| **السدادُ من العمولات اللاحقة** | ❌ **لا آليّة** | ❌ **جزءٌ من `ADG-8`** |

## وأدقُّ ما في القرار

**عبارتُك «إن كان الأنسبُ هندسيّاً فصلَ الثلاثة» تحسم اتّجاهَ الحلّ**:
**لا يُفتح `CHECK (balance >= 0)` ليصير الرصيدُ سالباً** — **بل تُضاف طبقةٌ
ثالثة.** **والرصيدُ يبقى غيرَ سالبٍ أبداً، والالتزامُ يُسجَّل في مكانه.**

**وهذا يحمي حارساً قائماً وسليماً**: **`CHECK` هو ما يمنع اليومَ سحبَ ما
ليس في المحفظة** — **وفتحُه لأجل `RQ-5` كان سيفتح باباً أوسعَ من المشكلة.**

```
AQ-3 = CLOSED
AQ-3 CONTRACT GAPS = 2   (ADG-7 لا طبقاتِ رصيد · ADG-8 لا سجلَّ التزامٍ ولا سداد)
LEDGER DECISION = طبقةٌ ثالثةٌ لا رصيدٌ سالب
```

**ولا يُمسّ دفترُ المال إلّا بقرارٍ صريح** — **وهذا صريحٌ والتنفيذُ مؤجَّل.**

# `AQ-4` — **ذرّيّةُ التدقيق** · **APPROVED**

## العقد

```
CRITICAL ACTION SUCCESS  ⇒  CRITICAL AUDIT SUCCESS
```

**في المعاملة نفسِها أو في وحدة النجاح المنطقيّة نفسِها.**
**ويشمل**: **الاسترداد · قيودَ المحفظة · السحوبات · شام كاش · العمولات ·
التسعيرَ والهوامش · الأدوارَ والصلاحيّات · الإيقافَ والحظر · الإعداداتِ
الحسّاسة · تبديلَ حساب الدفع المربوط · وتدخّلاتِ الطلبات الحرجة.**
**وغيرُ الحسّاس يبقى غيرَ متزامن.**

## المقابلةُ بالكود

**والحالُ يناقضه في كلّ فعلٍ حسّاسٍ قِيس:**

```go
// audit.go:53-62
go func() {
    ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
    defer cancel()
    if _, err := s.pg.Exec(ctx, `INSERT INTO audit_log ...`); err != nil {
        s.logger.Error("audit: تعذّر قيد الحدث", "action", action, "error", err)
    }
}()
```

**وثلاثةُ خصائصَ تجعله يناقض العقدَ نصّاً:**

| الخاصّة | الأثر |
|---|---|
| **`go func()`** | **الفعلُ يردّ ٢٠٠ قبل أن تُحاوَل الكتابة** |
| **`context.Background()`** | **سياقٌ منفصلٌ عن المعاملة** — **فلا يمكن أن يكون جزءاً منها بنيويّاً** |
| **`logger.Error` بدل `return err`** | **السقوطُ سطرُ سجلٍّ لا فشلُ فعل** |

## والأفعالُ الحسّاسةُ التي تستعمله — **قِيست**

| الفعل | الحال |
|---|---|
| **قيدُ المحفظة** `finance.wallet_apply` | **`s.audit` غيرُ متزامنة** |
| **قرارُ السحب** `finance.payout_decide` | **`s.audit` غيرُ متزامنة** |
| **تسويةُ السائق** `finance.driver_settle` | **`s.audit` غيرُ متزامنة** |
| **نقلُ حالة الطلب** `ops.order_transition` | **`s.audit` غيرُ متزامنة** |
| **تعليقُ المتجر** `ops.merchant_suspend` | **`s.audit` غيرُ متزامنة** |
| **منحُ دور** | **يُدقَّق خارجَ المعالج** — **وبالنمط نفسِه** |
| **إعادةُ كلمة المرور** | **`INSERT` خامٌّ بـ`_, _ =`** — **متزامنٌ وخطؤه مُهمَل** |

**فخمسةٌ من سبعةٍ غيرُ متزامنة، والسادسُ متزامنٌ ويهمل خطأه** — **ولا واحدٌ
منها في معاملة الفعل.**

## والقرارُ يقلب قراراً مكتوباً في الشيفرة

**التعليقُ في `audit.go` يبرّر الاختيارَ الحاليّ**: «**الكتابةُ في الخلفيّة
ولا تُفشل الفعل**» — **وهو اختيارُ توفّرٍ على حساب السجلّ.**
**وقرارُك يعكس الأولويّةَ للأفعال الحسّاسة وحدَها، ويُبقيها لغيرها.**

## وما يقوله هذا الترتيبُ عن الكلفة

**المرحلتان الأولى والثانية بيانتُهما كاملةٌ اليوم** — **وتحتاجان بابين
وشاشة.**
**والثالثةُ والرابعةُ تحتاجان نموذجَ بياناتٍ جديداً.**
**فالقرارُ يبدأ بما هو مبنيٌّ ومهمَل، لا بما يحتاج بناءً من الصفر.**

**ولا تُعاد اختراعُ بيانةٍ موجودة** — **قلتَها نصّاً، والقياسُ يؤيّدها:
`users.last_location` مخزَّنٌ منذ `0072` ولم يقرأه سطحٌ إداريٌّ قطّ.**

```
AQ-6 = CLOSED
AQ-6 CONTRACT GAPS = 1   (ADG-11 — لا سطحَ خرائطيَّ إطلاقاً في اللوحة)
OPERATIONS MAP GAPS = 7   (بلا تبديل — والمراحلُ ترتّبها ولا تزيدها)
STAGE 1 BLOCKED BY = بابٌ وشاشةٌ فقط
```

| البند | أيصير عيباً أو خطراً؟ | لماذا |
|---|---|---|
| **`ADG-1`…`ADG-11`** | **لا** | **عقودٌ وُضعت اليومَ ولم تُبنَ** — `PRODUCT REQUIREMENT` |

١٠** — **وسببُه مُوثَّق**: **انقلابُ الهرم (`ADG-5`) كُشف أثناء مصالحة
