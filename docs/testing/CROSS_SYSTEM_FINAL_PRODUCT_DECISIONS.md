# `XQ-1` — **تنقيةُ الخروج بحسب الدور** · **APPROVED**

## العقد

```
ROLE-SPECIFIC SERVER-SIDE OUTBOUND REDACTION
```

**وسياسةٌ واحدةٌ تحكم `REST` و`WebSocket` وأيَّ قناةٍ ثالثةٍ تحمل الكيانَ
نفسَه.**
**وممنوعٌ الاعتمادُ على إخفاءِ الواجهة، أو انضباطِ العميل، أو عضويّةِ الغرفة
وحدَها.**

> **«إذا وصلت البياناتُ غيرُ المسموح بها للطرف، فالخصوصيّةُ مكسورةٌ حتّى لو
> لم يعرضها الـUI.»**

## المقابلةُ بالكود

| القناة | الزبون | المتجر | السائق |
|---|---|---|---|
| **REST** | ✅ **٤ حقول** — `redactForCustomer` | ✅ **١٦ حقلاً** — `redactForMerchant` | ❌ **لا حارس** |
| **البثّ** | ⚠️ **٣ حقولٍ داخلَ `publishOrder`** | ❌ **لا شيء** | ❌ **لا حارس** |

**وموضعُ العلّة بنيويّ**: **التنقيةُ في طبقة `server` و`publishOrder` في
طبقة `orders`** — **فلا يمرّ بها.** **والنفيُ مقيسٌ صراحةً**:
`grep redact internal/orders/` **يردّ صفراً.**

## وقرارُك يحسم سؤالاً كنتُ سأسأله

**سألتُ**: **أتُنقّى في المحرّك أم تُلَفّ في الطبقة الأعلى؟**
**والجوابُ**: **«من جهة السيرفر عند حدود الخروج حسبَ الدور»** — **فالسياسةُ
مشتركةٌ والتطبيقُ عند كلّ مخرَج، لا في المحرّك ولا في العميل.**

**وهذا يوجب مُقدِّماً واحداً (`presenter`) يعرف الأدوارَ ويُستدعى من
الطرفين** — **لا نسخةً ثانيةً من `redactForMerchant` في `orders`.**

```
XQ-1 = CLOSED
XQ-1 CONTRACT GAPS = 3   (XG-1 · XG-2 · XG-3 — وصارت D20 · D21)
```

# `XQ-2` — **اللقطةُ الماليّةُ للطلب** · **APPROVED**

## العقد

```
EXISTING ORDER USES ITS FINANCIAL SNAPSHOT
```

**والنسبُ تُثبَّت لحظةَ نشوء الالتزام الماليّ** — **ولا يبدّل إعدادٌ لاحقٌ
اقتصادَ طلبٍ قائم.**
**ويشمل**: **عمولةَ المنصّة · ونسبةَ المندوب · ومصدرَ احتسابها · وهامشَ
التسعير · وكلَّ أجرٍ يدخل التسوية.**

## المقابلةُ بالكود

**والحالُ خليطٌ**: **بعضُه ملتقَطٌ أصلاً وبعضُه يُقرأ لحظةَ التسليم.**

| القيمة | أمُلتقَطةٌ اليوم؟ | الموضع |
|---|---|---|
| **سعرُ البيع وسعرُ الشراء** | ✅ **مُلتقَطان في `order_items`** — `unit_price` · `merchant_price` | **فالهامشُ يُحسب من لقطتين ولا يشيخ** |
| **أجرةُ التوصيل** | ✅ **مُلتقَطةٌ في الطلب** | `orders.delivery_fee` |
| **عمولةُ المنصّة** | ⚠️ **تُحسب لحظةَ التسليم** ثمّ تُلتقَط | `transitions.go:835` ← `merchants.commission_percent` **الآنيّ** |
| **نسبةُ المندوب** | ❌ **تُقرأ لحظةَ التسليم** | `pricing.RepCommission` ← `sales.commission_percent` **الآنيّ** |
| **مصدرُ الاحتساب** | ❌ **مثبَّتٌ في الشيفرة** | `transitions.go:948` |
| **`sales.activation_orders`** | ❌ **تُقرأ لحظةَ التسليم** | `transitions.go:1254` |

**والأثرُ المقيس**: **طلبان أُنشئا في الدقيقة نفسِها وسُلّما بعد تبديلِ
النسبة ⇒ عمولتان مختلفتان.** **وأسوأُ منه**: **طلبٌ أُنشئ ونسبتُه ٥٪ يُسلَّم
بعد رفعها إلى ١٥٪ ⇒ المنصّةُ تدفع على اقتصادٍ لم يُوافَق عليه يومَ البيع.**

**والقرارُ يقلب `XQ-2` من سؤالٍ إلى فجوةِ عقدٍ صريحة** — **وأربعُ قيمٍ من
ستٍّ تحتاج التقاطاً.**

```
XQ-2 = CLOSED
XQ-2 CONTRACT GAPS = 4   (عمولةُ المنصّة · نسبةُ المندوب · مصدرُها · عتبةُ التفعيل)
XQ-2 ALREADY SNAPSHOTTED = 2   (الأسعارُ والأجرة)
```

# `XQ-3` — **مكافأةُ هدف المندوب** · **APPROVED**

## العقد

```
NO REWARD FOR PARTIAL CONVERSION
```

**تبدأ مؤهَّلةً/معلَّقةً، ولا تصير مستحقّةَ الدفع إلّا بعد اكتمال التحويل
وثباته.**

## المقابلةُ بالكود — **وهي بعينُها `D2`**

```go
// server/leads_handlers.go:715-822  — convertLead، بترتيبها
mrch, err := s.catalog.CreateMerchant(...)      // ٢
_, _ = s.pg.Exec(... full_name ...)             // ٣  خطؤه مُهمَل
_, _ = s.pg.Exec(... password_hash ...)         // ٤  خطؤه مُهمَل
_, _ = s.pg.Exec(... district_id ...)           // ٥  خطؤه مُهمَل
s.grantSalesTargetIfAny(ctx, mrch.ID)           // ٦  ← تدفع مالاً
_, err = s.pg.Exec(... status = 'converted' ... )// ٧  ← وهنا يثبت التحويل
```

**فالمكافأةُ تُدفع في الخطوة السادسة والتثبيتُ في السابعة.**
**وإن سقطت السابعةُ**: **المتجرُ مُنشأٌ · والمكافأةُ مدفوعة · والمرشَّحُ باقٍ
`new`** ⇒ **يُعاد التحويلُ فيُنشأ متجرٌ ثانٍ وقد تُدفع مكافأةٌ ثانية.**

**والسبعُ كلُّها بلا معاملةٍ واحدة** — **وخمسٌ منها خطؤها مُهمَلٌ بـ`_, _ =`.**

**فالحالةُ التي منعتَها نصّاً — `PARTIAL CONVERSION + REWARD PAID +
BROKEN LEAD STATE` — ممكنةٌ اليومَ بثلاث خطواتٍ متتالية.**

```
XQ-3 = CLOSED
XQ-3 CONTRACT GAPS = 2   (الترتيبُ يسبق التثبيت · ولا حالَ «مؤهَّلة» في النموذج)
XQ-3 LINKED = D2
```

# `XQ-4` — **تطابقُ الطلب الخاصّ مع العقد الأساسيّ** · **APPROVED**

## العقد

# `XQ-5` — **التدخّلُ الاستثنائيُّ في طلبٍ قائم** · **APPROVED**

## العقد

```
NORMAL SUSPENSION != ACTIVE ORDER TERMINATION
```

**والتدخّلُ الاستثنائيُّ ليس `SUSPEND USER` بل مسارٌ صريح**:
`EMERGENCY / EXCEPTIONAL INTERVENTION` — **بسببٍ وفاعلٍ وطلبٍ متأثّرٍ
وإعادةِ إسنادٍ أو إلغاءٍ ومعالجةِ بضاعةٍ وأثرٍ ماليٍّ وإشعاراتٍ وتدقيقٍ
إلزاميٍّ وحالٍ نهائيّة.**
**وممنوعٌ استعمالُه لمخالفةٍ عاديّةٍ أو تعليقٍ روتينيّ.**

## المقابلةُ بالكود

| ما يوجبه العقد | الحال |
|---|---|
| **التعليقُ العاديُّ لا يقطع** | ⚠️ **لا يقطع الحالةَ فعلاً** — **لكنّه يمنع صاحبَها من إتمامها**: `RequireAuth` يردّ، فالسائقُ لا يستطيع `delivered` |
| **مسارٌ استثنائيٌّ مسمّى** | ❌ **لا وجودَ له** — **و`status` حقلٌ واحدٌ لا نوعان** |
| **سببٌ إلزاميّ** | ❌ **`PATCH /users/{id}` بلا حقل سبب** |
| **إعادةُ إسناد** | ⚠️ **موجودةٌ منفصلةً** — `POST /orders/{id}/assign` |
| **إلغاءٌ عند اللزوم** | ⚠️ **عبر الانتقال** |
| **معالجةُ البضاعة** | ⚠️ **`POST /orders/{id}/goods` قائم** |
| **الأثرُ الماليّ** | ⚠️ **تعويضُ السائق قائم** — **ولا يُربَط بالتدخّل** |
| **إشعارُ الأطراف** | ❌ **لا شيءَ مخصَّص** |
| **تدقيقٌ إلزاميّ** | ⚠️ **كلُّ فعلٍ مُدقَّقٌ وحدَه** — **ولا سطرَ يجمعها في حادثةٍ واحدة** |
| **حالٌ نهائيّةٌ للحساب والطلب** | ❌ |

**والقطعُ الحاليُّ ليس قطعاً بل شللاً**: **الطلبُ يبقى مُسنَداً والزبونُ
ينتظر والمتجرُ سلّم البضاعة** — **والمخرجُ الوحيدُ إعادةُ إسنادٍ يدويّةٌ لا
يعلم أحدٌ أنّها لازمة.**

**ولا استعلامَ «طلباتٌ بيد موقوفين» في اللوحة.**

```
XQ-5 = CLOSED
XQ-5 CONTRACT GAPS = 3
    XG-22  التعليقُ العاديُّ يشلّ إتمامَ الطلب القائم
    XG-23  لا مسارَ تدخّلٍ استثنائيٍّ مسمّى بسببٍ وأثرٍ وتدقيقٍ جامع
    XG-24  لا استعلامَ يُظهر طلباتٍ عالقةً بيد موقوفين
```
