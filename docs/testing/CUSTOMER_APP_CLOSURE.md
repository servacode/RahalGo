# ١ · USER JOURNEY FROM ZERO

**والمسارُ ليس خطّاً واحداً** — **بابان للدخول وبابان للطلب.**

```
تثبيت

      ├─ BrandIntroHost     ← شاشةُ الهويّة

      └─ حالاتُ الجلسة الأربع:

           guest     → **تصفّحٌ بلا حساب**  ← بابٌ ثانٍ

```

## بابا الدخول
| الباب | المسار |
|---|---|
| **كلمةُ مرور** | `POST /auth/login` → توكنان |
| **رمزٌ لمرّة** | `POST /auth/otp/request` → `otp/verify` — **ويُنشئ حساباً إن لم يوجد** |
| **تسجيلٌ كامل** | `signup/request` → `signup/verify` → `signup/confirm` |
| **استعادة** | `password/reset/request` → `verify` → `confirm` |
| **الضيف** | **بلا حساب** — تصفّحٌ وسلّةٌ، **والدخولُ يُطلب عند الطلب** |

## بابا الطلب
| الباب | المسار |
|---|---|
| **الطلبُ العاديّ** | تصفّح → صنف → خيارات → سلّة → عنوان → تسعيرة → `POST /orders` |
| **الطلبُ الخاصّ** | تبويبٌ مستقلّ → نصٌّ وعنوان → `POST /orders/custom` — **ولا سلّةَ ولا سعر** |

## بقيّةُ الرحلة
```
تتبّعُ الطلب (تبويب «طلباتي») → إشعارات → تسليم
→ تقييم (نجومٌ للطلب وللسائق) → شكوى (بنافذةٍ زمنيّة)
→ سجلٌّ · محفظة · مفضّلة · عروض · دعوة · دردشة · تذاكر
→ حساب: اسمٌ وصورةٌ وهاتفٌ وواتسابٌ وعناوينُ وكلمةُ مرور
→ خروج · أو حذفُ حساب
```

**⚠️ وما ليس في القائمة التي أعطيتَها ووُجد**:
**الضيف** · **الطلبُ الخاصّ** · **الدردشةُ الحيّة مع العمليّات** ·
**المحفظةُ ورصيدُها** · **الدعوةُ والمكافأة** · **التذاكرُ والشكاوى** ·
**اختيارُ المدينة** · **حذفُ الحساب** · **صندوقُ الإشعارات**.

**وما ليس فيه**: **لا دفعَ إلكترونيّ** — **نقدٌ أو محفظةٌ لا ثالثَ لهما.**

# ٥ · HOME / MARKETPLACE

## ما يراه أوّلاً
`GET /public/home` **يجمع في نداءٍ واحد**: **هويّةَ المنصّة** ·
**البانرات** · **الأقسام** · **الرفوف** · **مهلَ الدوران** ·
**هاتفَ الدعم** · **رابطَ التطبيق** · **حالَ الموقع**.

## الترشيحُ الجغرافيّ — **طبقتان مُثبَتتان**
| الطبقة | الأداة | متى |
|---|---|---|
| **دائرةُ المدينة** | `ST_DWithin` — `delivery.default_radius_m` **وصفرٌ يعني بلا حدّ** | **التصفّح** |
| **مضلّعاتُ المناطق** | `delivery_zones` — `ErrOutOfZone` | **الإنشاء وحدَه** |

**واختيارُ المدينة يدويٌّ ويُحفظ محلّيّاً** — **ولا يُربط بالحساب** (OBS-C2).

## التوفّرُ والسعر
**الصنفُ يحمل `available` و`sourceClosed`** — **والاقتراحاتُ تُرشَّح بهما.**
**والسعرُ من الخادم دائماً** — **و`pricing.margin_fixed` يُضاف قبل العرض.**

## ⚠️ ما يحتاج قراراً
**الصنفُ المحذوفُ أو المُبدَّلُ خياراتُه** — **يُرفض عند الإنشاء بـ`bad_items`**
(**`RV-4`** يسأل: **ماذا يرى الزبونُ فعلاً؟**).
**والسلّةُ لا تُراجَع قبل ذلك** — **يُكتشف الخللُ عند الضغط الأخير.**

# ١٨ · ما يجب أن يناقشه المالك — **٧ فقط، مرتّبةً**

### ١ · **السلّةُ تبقى بعد الخروج** — `OBS-C1`
**زبونٌ يخرج على هاتفٍ مشترَك، فيجد الداخلُ بعده سلّتَه.**
**والسؤال**: **أتُمحى السلّةُ عند الخروج، أم تبقى لأنّ من يخرج ويعود
هو نفسُه غالباً؟**

### ٢ · **«refunded» تظهر بالإنكليزيّة** — `OBS-C3`
**ثلاثَ عشرةَ حالةً لها نصٌّ عربيٌّ، والرابعةَ عشرةَ لا.**
**والسؤال**: **ما النصُّ العربيّ؟ «أُعيد المبلغ»؟ وأتُعرض للزبون أصلاً
أم تُدمج مع «أُلغي»؟**

### ٣ · **أيفتح الإشعارُ الطلبَ بعينه؟** — `U46`
**«طلبُك في الطريق» تفتح الشاشةَ الرئيسيّة.** **والزبونُ يبحث عن طلبه
بيده.** **وهذا يغيّر تصميمَ اختبارات الإشعارات كلِّها.**

### ٤ · **أيرى الزبونُ سائقَه على الخريطة؟** — `OBS-C4`
**المحرّكُ يملك الأثر، والخرائطُ مبنيّة، وتطبيقُ الزبون لا يعرضها.**
**والسؤال**: **أهو قرارُ منتجٍ مؤجَّل أم ميزةٌ لم تُبنَ بعد؟**
**وهو أكبرُ فرقٍ بيننا وبين تطبيقاتٍ يعرفها الزبون.**

### ٥ · **الطلبُ الخاصُّ — أهو طلبٌ ثانٍ أم بابٌ ثانٍ؟** — `D-04` + `D6` + `D8`
**تعليقُه يقول «طلبٌ كسائر الطلبات» وحرّاسُه أربعةٌ أقلّ.**
**والسؤال ليس تقنيّاً**: **أنريد للطلب الخاصّ حرّاسَ العاديّ كلَّها، أم
هو بابٌ مقصودٌ أوسع لأنّ السائقَ يتّفق مع الزبون مباشرةً؟**
**والجوابُ يحسم ثلاثةَ عيوبٍ وقراراً.**

### ٦ · **ماذا يرى الزبونُ حين يفشل طلبٌ نجح؟** — `R8`
**نجاحٌ ثمّ انقطاعٌ ⇒ يقرأ خطأً، ويعيد فيُردّ عليه «قيد التنفيذ» يوماً.**
**والسؤال**: **أنُظهر له «طلبُك قد يكون وقع — راجع طلباتك» بدل رسالةِ
خطأ؟** **وهي تجربةٌ لا شيفرة.**

### ٧ · **أنترك سقفَ الطلبات المفتوحة معطَّلاً؟** — `D4`
**بالافتراضات لا سقفَ إطلاقاً.** **والسؤال**: **أنشعله الآن (فيلزم توثيقُ
واتساب للجميع)، أم نفصله عن واتساب أوّلاً؟** — **وهذا قرارُ منتجٍ قبل أن
يكون إصلاحاً.**
