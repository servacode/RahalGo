# ٢ · ما كشفه القياسُ ولم يكن معروفاً

**سبعُ ملاحظاتٍ جديدةٍ خارجَ السجلّات المجمَّدة** — **وثلاثٌ منها ثقيلة.**

## ⚠️ `XOB-1` — **البثُّ الحيُّ يتجاوز حرّاسَ الخصوصيّة كلَّهم**

**والتنقيةُ في طبقة `server` والبثُّ في طبقة `orders`** — **فلا يمرّ بها.**

```go
// orders/service.go:114-127 — publishOrder
event := map[string]any{"type": "order", "order": o}
s.pub.Publish("ops", event)
s.pub.Publish("merchant:"+o.MerchantID, event)   // ← الطلبُ كاملاً

cust := *o
cust.MerchantID, cust.MerchantName, cust.MerchantLogoThumb = "", "", nil
s.pub.Publish("customer:"+o.CustomerID, ...)     // ← ثلاثةُ حقولٍ فقط

if o.DriverID != nil { s.pub.Publish("driver:"+*o.DriverID, event) }
```

**ومقابلُه في REST**: `redactForMerchant` **تمحو ستّةَ عشرَ حقلاً** —
**اسمَ الزبون وهاتفَه وعنوانَه ونقطتَه · وهويّةَ السائق وهاتفَه · وإثباتَ
التسليم · والمبالغَ كلَّها.**

**فالمتجرُ يقرأ في القناة الحيّة ما مُنع منه في الباب**: **هاتفَ الزبون
وعنوانَه ونقطتَه على الخريطة، وهاتفَ السائق، وإثباتَ التسليم، والمبلغَ
الكامل.**

**وقِيس النفيُ صراحةً**: `grep redact internal/orders/` **يردّ صفراً.**

**والزبونُ كذلك**: البثُّ يمحو ثلاثةَ حقولٍ و`redactForCustomer` تمحو
**أربعة** — **فـ`OfferedDriverName` يصل في القناة الحيّة ولا يصل في الباب.**

## ⚠️ `XOB-2` — **هاتفُ السائق: يُمحى للمتجر عمداً ويصل الزبون**

| الطرف | `DriverPhone` |
|---|---|
| **المتجر** | ❌ **يُمحى صراحةً** — `merchant_privacy.go:44` |
| **الزبون** | ✅ **يصل** — `redactForCustomer` لا تمسّه |

**والعقدُ يقول**: «**الزبون: لا يرى driver phone**».
**فالحقلُ نفسُه محميٌّ في جهةٍ ومكشوفٌ في أخرى** — **وليس سهواً في الحارسين
معاً، بل قرارٌ اتُّخذ لأحدهما ونُسي في الآخر.**

## ⚠️ `XOB-3` — **الطلبُ الخاصُّ لا يُبثّ لصاحبه**

**قِيس بعدّ النداءات في الملفّين:**

| الحارس | `service.go` (عاديّ) | `custom.go` (خاصّ) |
|---|---|---|
| `cashBlocked` | **١** | **٠** ← `D6` |
| `RequireWhatsApp` | **١** | **٠** ← `D8` |
| `INSERT order_events` | **١** | **٠** ← `D9` |
| **`publishOrder`** | **٣** | **٠** ← **جديد** |
| `checkOpenLimit` | ٣ | ١ ✅ |

**و`custom.go:213` يبثّ `ops` وحدَها ببرقيّةٍ فارغة** (`{"type":"order"}`).
**فغرفةُ الزبون لا تُخطَر بإنشاء طلبه الخاصّ إطلاقاً** — **وشاشتُه تنتظر
حدثاً لا يأتي حتّى أوّلِ انتقالٍ لاحق.**

**وهذا رابعُ فرقٍ بين العاديّ والخاصّ** — والثلاثةُ الأولى مسجَّلةٌ عيوباً
(`D6` · `D8` · `D9`)، **والرابعُ لم يُسجَّل.**

## `XOB-4` — **٢٤ إشعاراً للمستخدمين بلا توجيهِ تطبيق**

**جُرد المحرّكُ كلُّه بمطابقة الأقواس**: **٤٩ موضعَ إشعار.**

| الصنف | العدد |
|---|---|
| **موجَّهٌ بـ`Apps`** | **١١** |
| **بلا توجيهٍ — لمكتب العمليّات** | **١٤** (`NotifyOps`/`NotifyRoles` — والموظّفون على الويب فلا يعنيهم) |
| **بلا توجيهٍ — لمستخدمٍ حقيقيّ** | **٢٤** |

**و«فارغةٌ تعني كلَّها»** نصّاً في `notifications.go:141`.
**فمن يحمل تطبيقين — والمندوبُ والسائقُ يحملان تطبيقَ الزبون أيضاً — يسمع
الإشعارَ مرّتين على جهازٍ واحد.**

**والأحدَ عشرَ الموجَّهةُ تثبت أنّ النمطَ معروفٌ ومُطبَّق** — **فالغيابُ سهوٌ
لا قرار.**

## `XOB-5` — **الراصدُ يبتلع إنذاراتٍ حين لا يتغيّر مفتاحُه**

```go
// orders/watchdog.go:104-112
key := ""
for _, a := range alerts { key += a.OrderID + a.Reason + "|" }
if key == lastKey { continue }   // ← لا بثَّ ولا تصعيد
```

**فطلبٌ ثانٍ يدخل الإنذارَ بينما الأوّلُ ما زال فيه ⇒ المفتاحُ يتبدّل ويمرّ.**
**لكنّ طلباً يخرج ويدخل آخرُ بنفس السبب في الدورة نفسِها ⇒ مفتاحٌ مطابق
⇒ صمت.** **وهو أضيقُ من `R22` وأدقُّ منه**: `R22` عن `alerted_at`، **وهذا عن
مفتاح المقارنة قبله.**

## `XOB-6` — **`escalate` يسم قبل أن يُشعر**

```go
UPDATE orders SET alerted_at = now() WHERE id = $1 AND alerted_at IS NULL
...
s.notify.NotifyOps(ctx, ...)   // ← بعد الوسم
```

**فإن سقط الإشعارُ بقي الوسم** — **ولا إنذارَ ثانٍ أبداً.** **وهو `R22`
بعينه، مُثبَتٌ هنا في سياق المنظومة.**

## `XOB-7` — **الطلبُ الخاصّ يُنشئ تحويلاً في خيطٍ منفصل**

```go
// server/customer_handlers.go:362
go s.autoTransfer(context.WithoutCancel(r.Context()), o.ID, userIDFrom(r))
```

**خيطٌ يمضي بعد أن يُردّ على الزبون** — **فإن سقط لا يعلم أحد، ولا سطرَ
تدقيقٍ ولا ردَّ خطأ.** **ويلتقي مع `R21`.**
